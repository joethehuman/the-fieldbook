# Reading pages and link metadata

The server application renders published Docs (`/docs/:id`), Updates (`/updates/:id`) and Courses (`/courses/:id`) on the server. A course URL now opens the player at its first unfinished lesson, or lesson one when new or already completed. A specific lesson uses `/courses/:id?lesson=:lessonId` inside the same reader shell and remains readable without JavaScript. Validated curriculum context and return paths are preserved. Search keeps its published item and lesson destinations. The browser-local demo continues to use its own local data.

## Access and response behavior

Administration has readable section paths such as `/admin/content`, `/admin/people`, `/admin/groups`, `/admin/progress` and `/admin/settings/identity`. Saved content editors use `/admin/content/:id/edit`; people, teams, groups, curricula and progress details include their stable record IDs. `/admin` redirects to Content. Direct requests recheck role and record access on the server; unavailable or restricted destinations return 404. Refresh restores saved data at that destination. New content starts at `/admin/content/new/:kind` and replaces that address with the saved record address after its first successful save. Unsaved edits remain protected by the existing navigation prompts and browser refresh warning.

Courses collections use `/courses/yours`, `/courses/for-you`, `/courses/in-progress`, `/courses/completed`, `/courses/all` and `/courses/curricula`. Their controls update browser history, and course/curriculum links carry a validated `from` path so exiting returns to the launching collection. Team report details use `/team/people/:id`, with the existing server reporting scope. Refresh, direct entry and Back/Forward preserve these destinations; search, sorting and pagination remain temporary view controls. The browser-local static demo uses the same destination paths after `#`; its hosted path remains unchanged. This routing change requires no migration or provider configuration.

Manage organization in the account menu and Administration in the breadcrumb return an Admin section or content editor to the Content landing screen. My team’s progress and the Team progress breadcrumb return a manager’s member details to the overview. Selecting an already open landing screen closes the menu without routing, a new history entry or header progress. Existing leave guards apply before returning: Cancel keeps the current editor or form, while Confirm completes the selected destination. Server roles and reporting scope remain authoritative; the editor keeps its dedicated layout.

The installation’s existing public/private setting controls reading pages; there is no separate SEO or public-site configuration. Anonymous public requests can read only published snapshots. Private requests verify the account on the server before querying the item. Signed-out or disallowed accounts go through the branded sign-in flow with their destination preserved. Missing, deleted, unpublished, wrong-type items and missing lesson destinations produce a real HTTP 404. Provider failures remain server errors, not missing pages.

Docs and Updates lists and articles use a small published index and one published body read for a detail page. Their layout, page and metadata share request-local React `cache` lookups. The server checks session and installation access before using cached published data, then checks the returned item’s publication state and type before rendering. Groups guide Updates recommendations, never content access; real group metadata is not sent to guests. No draft snapshot, quiz answer key, learner progress or administration record enters the reader payload. A signed-in account's display name appears in its private, no-store HTML. Feedback loads separately from the article through an authorized lookup. On public installations, a signed-out visitor can save feedback using a browser-specific cookie; private installations still require sign-in. These routes never load `/api/workspace`.

Docs, Updates and Courses use Next links for list cards, lesson links, the document tree, breadcrumbs, search results and previous/next links. The installed workspace layout keeps one app bar, sidebar, search controller and account menu mounted while navigating between these sections, Team and Administration. Direct URLs and links without JavaScript still render server HTML. Dynamic article links wait for fresh server content; there is no persistent article prefetch cache or per-link loading text. An Update article skips the list-index read after the reader layout is already mounted. Course playback receives one redacted published body and, for signed-in readers, the current progress for that course. Lesson completion and quiz attempts use the existing server grading endpoint; no answer key reaches the browser. Guest progress remains in the browser and import after sign-in stays explicit. Course playback does not call `/api/workspace`. The existing unsaved-edit guard still protects navigation out of authoring and administration.

The Docs sidebar presents top-level sections as fixed headings. Their documents appear directly below, while subsections expand on demand and open automatically for the selected document. On a narrow screen, choosing Docs from the main menu leaves the menu open for browsing; choosing a document closes it to show the article. Courses and Updates continue to close the menu when selected.

The installation root redirects to `/courses`. The destination is defined in `lib/navigation.ts` so it can move to `/updates` later. Team progress shares the reader shell but gets only the authorized people, teams, groups, progress and compact published course records needed for reporting. It does not fetch the full workspace or feedback and does not cache personal report data. Administration retains its scoped editing data and unsaved-work guard inside that shared frame. Current section URLs are `/courses`, `/updates` and `/docs`; pre-public legacy aliases are not maintained.

Authored hyperlinks follow the reading context without extra link settings in saved Markdown. Hyperlinked lesson and course overview text opens in a new tab so the current course step remains available. In Docs and Updates, relative links and absolute links to the current installation stay in the same tab; outside HTTP(S) links open in a new tab. Links opening separately include a screen-reader announcement and do not expose the opener. Course progression buttons, breadcrumbs, document navigation and media controls retain their own navigation behavior.

## Metadata and caching

Each readable item supplies a title, description, canonical URL, Open Graph and Twitter metadata. URLs use the configured trusted application origin. Every URL uses the same installation-level image and a large-image Twitter card, without item media or expiring Storage URLs. The PNG contains only the installation's deliberately public name, domain and accent, never an item title, summary or existence signal. Private authorized pages are marked noindex; anonymous private requests receive only generic metadata and the approved public sign-in identity. See [link-sharing cards](og-cards.md) for privacy, caching and the template boundary.

Reading routes remain dynamic and responses are private/no-store. Only the published Docs/Updates index and redacted article bodies use a shared Next data cache, with a five-minute fallback refresh. Successful publish and unpublish operations through the web editor or administrator MCP expire that cache immediately. Installation settings, account checks, group relevance, feedback and course state remain request-time data; no user data, draft, full page or HTML response is shared in the cache. Metadata streaming is disabled so access/existence checks finish before HTTP headers are committed, including for regular browsers. The shared reader layout rejects unavailable items on direct HTML requests before rendering the shell to preserve real 404 responses; client navigation rechecks them in the page. Browser back/forward within the reader uses Next client navigation while retaining request-time access checks.

The next request reflects publication changes made through Fieldbook and any change to installation access. Direct database edits bypass application invalidation and may remain in the published-content cache until its fallback refresh. Content already delivered to an open page cannot be recalled. Application cache controls cannot remove third-party preview caches or copies previously downloaded by a visitor. Operators should not add CDN caching rules that override the application’s private/no-store headers.

Cookie sessions are refreshed in the Next.js request proxy for reading routes, before Server Components run. The proxy does not trust the cookie session as identity; normal server authorization still verifies the user and active profile. The independent configuration read starts alongside user verification, and the access rule runs before any item or index read. Reading components use a read-only cookie client; APIs retain their existing cookie-writing behavior.

## Verification

Run `pnpm test:reading` after both builds, using the synthetic production build values documented in CONTRIBUTING. It exercises the built application against a local protocol fixture, including raw HTML/metadata/status checks, public/private transitions, redaction, simulated session refresh, no-JavaScript rendering and desktop/phone interactions. It uses the same local fixture ports as account tests, so run suites sequentially. No hosted credentials are needed or permitted.

These checks do not establish hosted Google OAuth, production provider behavior, search-engine rankings or actual third-party previews. No migration or extra service is required. Sitemaps, robots expansion and SEO administration remain outside this behavior.

## Docs reading navigation

Navigation within and between Docs, Updates and Courses (including curricula) keeps the current page visible while the next page resolves, without header progress. Entering Administration from those screens retains the header progress bar; other existing shell transitions keep their progress behavior. When shown, the fixed-width progress segment slides in from the header’s left edge, then continues its existing back-and-forth motion. It appears immediately for a pending transition and disappears when that transition ends, with no trigger delay or minimum visibility. Reduced-motion settings retain the static indicator. The demo initially renders its complete default profile-selection page, including Hoolibook identity and all three profiles. Selection becomes available after browser storage loads; saved profile names and branding then replace the defaults, or a saved active profile resumes the workspace. Storage errors and Reset demo remain on that same page. The demo preloads its local Geist font with optional display: if it arrives too late for first paint, the browser keeps the fallback font for that page rather than changing text wrapping and card height. It does not show a full-screen startup loader or add an animation or loading delay.

Docs use left-aligned section/folder navigation with the current document highlighted. On desktop the document tree scrolls independently of application navigation and account controls. Tab-local scroll/disclosure preferences are optional and do not change document order or access. Short screens and larger text retain an outer-sidebar scrolling fallback.

`/docs` opens the first published document in sidebar order, including a subsection document when the first section has no direct documents. The route shows a simple empty state when no documents are published. Individual Docs pages use the sidebar and previous/next links for navigation, without a back-to-index link.

Articles with H2/H3 headings have an **On this page** outline. It stays visible beside the article on wide screens and becomes a compact disclosure on smaller screens. Headings have shareable links; repeated headings receive unique suffixes. These links derive from the rendered Markdown rules, so code examples are never mistaken for headings. Editing a heading can change its anchor; unchanged headings retain their anchors unless an earlier duplicate changes their suffix.

Previous and next links follow the same published document sequence as the sidebar, crossing section and folder boundaries. Search and collapsed sections do not change the sequence. The first and last document omit their unavailable direction. Publication changes made through Fieldbook appear on the next server request without a workspace load.

The server authorizes access before fetching the compact Docs and Updates index. The paginated read projects only published navigation, card, ordering and recommendation fields; the server discards group IDs before serializing reader data. The published index and body cache is separated by installation backend and governance revision; account and installation checks remain request-time. Index fields scale with catalog size; this is not a transactional snapshot across simultaneous publication changes. A document unpublished through Fieldbook returns the existing missing-page response when opened after cache expiration.

Run `pnpm test:reading` after both builds for server HTML/private redaction, publication changes, no-JavaScript links, repeated-heading fragments, browser history, large document trees and responsive reading checks. Fixtures use synthetic local services, not hosted authentication or production data.

## Administration data loading

People and Teams use a complete account and organization list without course bodies or learning histories. Names and emails remain searchable locally, with 25 visible rows per page. Opening Courses & progress loads that person's complete history; organization reports and learning-group views request their complete reporting inputs separately. A pending section keeps the current panel and shell visible, with a spinner on the requested desktop section and an Opening message in the narrow section picker. Failed reads retain the current view and show a retryable error.

Recently deleted loads its deletion list, actor names and cleanup status separately. All administration reads retain request-time administrator checks and `no-store` responses. Browser caches belong to the signed-in administration session and are invalidated after mutations.

This version requires the additive `admin_people_reads` migration before application deployment. It adds the server-only `fb_admin_people_snapshot(uuid,uuid)` function and content-ID indexes on progress and feedback; it leaves existing report permissions and the broader governance read intact. On an existing installation, apply it in isolation first, then during a quiet period: regular index creation briefly locks writes. A five-second lock timeout makes a busy migration fail instead of waiting indefinitely. Follow the migration procedure in [installation](installation.md).
