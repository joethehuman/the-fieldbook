# Fieldbook design system

Fieldbook's design system is the shared interface code in `components/` and `styles/`, together with the usage rules in this guide. The installed app and separate interactive demo use that code. The demo-only `/ui` catalog shows representative examples, not a complete component inventory or the source of the components.

Its foundations are shadcn/ui source composition, Radix interaction primitives, Tailwind CSS 4, Geist, Lucide, and semantic theme variables. This guide is for contributors changing the interface.

## Where the interface lives

| Layer | Location | Owns |
| --- | --- | --- |
| Theme | styles/tokens.css | Colors, type, spacing, radii, and page measures |
| Primitives | components/ui/ | Controls, fields, dialogs, menus, cards, tables, and feedback |
| Patterns | components/patterns/ | Repeated page composition and navigation |
| Product components | components/ | Reusable feature UI, such as `CourseCard` and `CurriculumCard` |
| Application layout | styles/layout.css | Shell and feature geometry |
| Reading and artwork | styles/content.css and styles/artwork.css | Authored content and decorative media |
| Workspace presentation | styles/learner.css | Neutral shell and learner styling using shared tokens and existing layouts |

Before building a control, card, or page pattern, check the shared components and the `/ui` examples. Reuse or extend an existing component when it already owns the behavior. For example, `CourseCard` and `CurriculumCard` compose the shared `LearningCard`; the demo and installed Updates pages both use `UpdateCard`.

Single-choice dropdowns dismiss when any enabled option is activated, including the current or default selection. The shared Select preserves its value without firing a value-change callback on reselection. Keep disabled choices unavailable, return focus to the trigger, and distinguish a completed touch from scrolling or cancellation. Select owns this behavior for sorting, filters, forms, compact section navigation and editor language controls. Multiple-selection lists retain their existing selection workflow.

Generated card artwork uses a consistent 1.5rem short title at every browser width. Horizontally scrolling CourseRow strips use a subtle 0.5rem edge fade only where more content is hidden, using the shared header fade’s tapered profile and reaching full transparency at the clipping edge to avoid a hard cutoff.

CourseCard owns the deadline cue in both apps. Overdue assigned courses show “N days past due” in the semantic destructive color; upcoming deadlines and “Due today” use muted text. Completed courses, guests and disabled due dates omit the cue.

Put new reusable controls in `components/ui/`, repeated composition in `components/patterns/`, and reusable product UI in `components/`. Keep route-specific data fetching, permissions, mutations, and route destinations in the owning app or demo feature. A one-off layout can stay local; move it into the shared library when reuse warrants it. Do not copy a reusable interface between the installed app and demo or build a second feature-specific control system. Avoid broad overrides and components with options for every possible layout.

## Compose a page

- Use SectionHeader for a section's title, description, and actions. Use CollectionControls or CollectionToolbar for search, sort, filters, and creation actions. The compact Admin section picker uses the same visible groups and headings as the desktop sidebar: Publishing, People & Progress, and Organization Settings. Group labels are muted, non-selectable headings; existing role filtering and destination behavior remain shared.
- Use a consistent heading action area for Admin collection creation; pinned hierarchy controls keep their creation action within the sticky area. At narrow admin content widths, search takes a full row and labeled filters and sort choices share the next row. Keep essential names readable and multi-column reports horizontally scrollable. On narrow Admin layouts, place hierarchy counts on the second row, left aligned with the visible selection checkbox; preserve their vertical alignment with row menus and the checkbox’s larger touch target. Settings forms retain their section grouping with smaller insets. These composition rules follow available space; touch sizing also covers hybrid inputs and portaled admin menus and dialogs, independently of the writing editor's input rules.
- Use Field, FieldDescription, and FieldGroup for forms. Associate help and errors with controls, mark invalid fields, and keep labels visible. FieldError aligns its message and dismiss button vertically, including when the message wraps.
- Use Button for commands; use an actual link for navigation. Use Tabs for panels, FilterOptions for collection filters, SortPicker for ordering, and DropdownMenu for actions. Text commands, including ghost buttons with icons, retain Button’s shared horizontal padding. Align them through their surrounding layout rather than stripping padding from their hover or disabled surface. Zero-padding exceptions belong to inline links, icon-only controls or specialized patterns with their own geometry.
- Teams use a chart at wider widths and a searchable, paginated directory on phones. Phone selection controls are immediately available; Select multiple switches the wider chart to a selectable table. Team and group directories preserve search, filters, sorting, pagination, valid row selections, and scroll position while opening details and returning through browser history or the in-app return control. Return focus to the directory heading without moving its restored scroll position. Entering another administration section or starting a new session starts fresh; accepted detail navigation clears transient detail forms. Completed actions clear their selection, and unavailable records are excluded from action targets.
- Use DataTable with a declared column schema for application records. Keep horizontal overflow inside TableContainer. Plain tables remain appropriate for authored content.
- Admin collection and assignment searches match titles or names, ignoring case and surrounding spaces. People searches also match email addresses. Keep descriptions, status labels, manager names and content text out of ordinary name searches; display metadata does not automatically become searchable. Hierarchy choosers may explicitly include parent paths. Feedback and review screens retain searches over their visible comments and details. Filtering preserves the chosen sort and selection behavior.
- Authored tables use native BlockNote table blocks, including column widths, header rows and columns, row/column movement, selection and clipboard behavior. Store their layout in the structured document. Keep wider tables horizontally scrollable within writing and reading surfaces. Legacy Markdown table width comments remain supported by the importer and Markdown reader/exporter; do not restore the retired editor table controller or its resize limits. See the table-grip integration below for the scoped completed-click menu behavior.
- Content feedback starts a new entry for each interaction. A thumb saves immediately; its optional comment updates that entry. Successful submission or dismissal resets the form. Administrator feedback uses compact single-line table rows with bounded content titles with inline versions (omitted for general feedback), a shared title tooltip only when the text is truncated, an 80-character comment excerpt, an accessible comment icon opening the full-comment dialog, and a pinned action menu. Rating-summary pills toggle the table rating filter; their counts and percentage reflect the current content and search scope, so both rating counts remain available while switching. The content filter uses a searchable picker; the collection search matches content titles and comments. Keep the search query in its field rather than duplicating it as an applied-filter chip; keep the result toolbar and selection column stable as matching counts change. Feedback deletion uses the shared individual and bulk action controls with permanent-delete confirmation.
- Authoring uses native BlockNote code blocks with a dark language header and themed language menu. Preserve native text editing, selection, code padding and scrolling. Shiki highlights the selected language; new blocks use Plain Text. The static reader retains browser-local language detection for unlabeled Markdown, syntax highlighting and its Copy action. Preserve explicit language labels and code text through storage and Markdown export; unsupported languages remain readable as plain text. Do not impose the retired editor’s code height or selection controller.
- Use shared dialog and picker patterns. Keep search and actions reachable while result lists scroll. Preserve keyboard selection, dismissal, and focus return. Assignment selection uses a tall Available / Assigned transfer dialog: each pane has its own search and section headings that stay pinned until the next section replaces them, with matching included teams shown in their source hierarchy; direct Add/Remove actions update sources, and expanded sources explain included team branches. Audience rows keep the group or team icon, name, compact people/team metrics and action on one line. Long names truncate while retaining their full accessible labels; guest and inherited-source details use labeled inline icons. Team-count chevrons expand branches without shifting the leading icon, and disclosures reflect their open state. Direct assignments have their own heading above Through curricula. Only top-level sources appear initially; overlapping coverage may appear under each source. Included child rows have disabled Remove controls; saved direct links stay intact and can be managed within the source disclosure. Curriculum sources remain visible and cannot be removed from a course. Multi-item additions retain existing assignments and label pending choices To add. On phones, show one full-height pane with Available / Assigned controls rather than stacking lists. Use native lists and buttons, announce transfers, and retain focus after a row moves; these rows are not ARIA listbox options. Course and curriculum pickers opened from groups or teams use one Manage Courses action and the searchable Available / Assigned transfer layout. Saved direct links load on the right; additions and removals save together. Curricula expand to show included courses with disabled individual removal. Bulk management labels partial assignments and preserves them unless the administrator removes them or assigns the item to all selected audiences. Updates use the audience picker in their editor, and the compact transfer for live group recommendations from content and group pages; Manage Updates shows current group recommendations under Assigned and saves additions and removals together, preserving untouched partial recommendations in bulk management. Updates are recommendations without a completion requirement. Group and team row, bulk and detail menus expose the same course actions. Curricula expose one Manage Audience action for individual and bulk selections; it loads current team/group links and saves additions and removals together, retaining untouched partial links for bulk selections. Group menus also manage live Update recommendations; team Update targeting is managed in the Update editor. Leave space around picker searches for the complete focus ring.
- Use the shared publication, progress, empty, error, loading, and pending-save states. Publication state and draft-save state remain separate. Content listings show newer draft edits; editor headers keep publication badges and use Publish eligibility for pending changes.
- Failure and unavailable-action messages must be dismissible. Use Alert for operation failures; destructive alerts and alerts with `role="alert"` include a close control. Other failure notices opt in with `dismissible`. Dismissal hides notification copy without changing permissions, validation, unsaved work or recovery state. Keep necessary retry/recovery controls outside the message. Clear transient notification copy with `onDismiss`, or use `dismissKey` for a new attempt with the same message. Keep copy short: the reason, next action and reference ID when available. Focused messages have no outline; their controls use a neutral focus indicator. The shared transition animates occupied space and respects reduced motion.
- For explicit manual saves, compare the draft with its saved baseline in the owning form and use SaveChangesControl. Keep Save visible but disabled when nothing changed. Settings save areas stay in normal flow at the bottom of their card or after the final section, using SettingsSection or SettingsPageActions. Enabling Save must not turn the footer into a floating overlay or hide its guidance. Only Docs navigation and Categories use the top-pinned PendingChangesBar for long reorganization tasks. Keep the gray save area compact and place a quiet Discard action just below it when editing begins. Announce unsaved and saving states to assistive technology without adding visible status text; explain any other reason that blocks saving. Guard form submission as well, so pressing Enter cannot save an unchanged draft. Automatic draft saves and publication actions have their own states.

A parent layout owns the space between sections. A field group owns the space between fields. Individual controls should not add compensating margins. Use semantic theme tokens rather than literal interface colors; decorative artwork and validated runtime branding are separate cases. Text must remain readable when it wraps or grows.

## Layout and accessibility

The sidebar, header and Search / Ask AI form one universal workspace shell. `WorkspaceFrame` and `AppBar` apply the same `workspace-chrome` styling in learner, management and editor routes. Keep the white main background, header geometry, centered search fit, and native mobile editor scrolling and toolbar behavior consistent. Navigation opens with a gentle 320ms transition and closes in 220ms; the compact drawer and backdrop enter and leave together. Keep closed navigation inert during its exit fade, respect reduced motion, and never animate a responsive layout change. Search opens on focus or Cmd/Ctrl K, including with an empty query; clearing returns to Search while dismissal preserves the query, conversation and draft. Empty Search offers up to four published suggestions from existing unfinished assignments, audience recommendations, recent Updates and ordered Docs, followed by Docs, Courses and Updates browse links. Suggestions load on demand in the installed app and use the same selection rules in the demo. Desktop search sizes the suggestion list to its content. Its right-aligned Escape hint shares a row with Browse links in suggestions and the chat notice in Ask AI. Keep those links and the notice on one line; when space is limited, only the hint moves below, left aligned with a small gap. Results retain a separate footer with equal space above and below the hint. Command K and Escape hints are passive keycaps with compact line height and equal horizontal padding. On compact screens, search uses a full-screen dialog sized to the visual viewport, with the field and Close action pinned above the scrollable content and the chat composer above the keyboard. Reuse the shared dialog focus and scroll ownership, preserve queries and chat across dismissal, and retain the editor layout behind the dialog. A first touch focuses a text field without requesting additional browser scrolling, while retaining native caret and selection gestures; the outer dialog clips overflow and leaves scrolling to its results and transcript. Browse links use the same icons as primary navigation. Search and Ask AI use the existing tabs and embedded composer; keep empty states compact so they do not compete with results or the conversation. Search results, citations, unsaved-change guards, keyboard dismissal and reduced-motion behavior keep their existing owners.

Learner routes additionally opt into `WorkspaceFrame`'s `learner` styling. Use the existing neutral black-and-white tokens throughout learner, management and editor views. Color comes from installation identity, authored card artwork and semantic status labels; do not introduce a learner palette or a colored progress surface. All views use the same Geist family and shared heading, control and prose styles. Refinement belongs in subtle borders, surfaces, selection cues and precise alignment, preserving established page insets, card proportions, content arrangements and responsive layouts. Progress captions retain clear space from both their percentage and ring; course rows stack when enlarged text reduces usable width. Cards retain authored artwork, deadlines and version-aware progress. Reading keeps its centered measure and responsive outline. The course player exposes the current lesson as the current step and retains independent outline scrolling and focus on lesson transitions. The main workspace remains the page scroller. The `/ui` reading, learning, search and dropdown examples use the actual shared components.

The shared app header centers the search field horizontally over the workspace and vertically with the installation name and sidebar toggle. If the centered field would overlap editor publication controls, search alone switches to its icon and full-width panel. This measured fit rule does not change the navigation or editor breakpoints. Search panels close when their presentation changes, preserving the query. The search clear icon sits inside the field with reserved text padding, keeping the field width stable as authors type. A consistent page inset adds breathing room below search and visually aligns page headings with the first primary sidebar item. Top-right breadcrumbs are omitted; the sidebar, account menu and contextual Back actions provide navigation. Narrow Docs place the title area before the On this page disclosure; wide Docs retain the outline beside the article. The shared app header fades its bottom edge only when workspace content has scrolled beneath it. Header and pinned-title fades share a short, light transition; keep them non-interactive and leave the unscrolled edge clear. Content editors put save status and publication actions in the shared app header. Compact navigation uses a muted spinner while saving/uploading and a check only after a confirmed save, centered in a fixed icon area alongside the publication badge and button. New unsaved drafts leave the icon area empty. Screen readers receive the live save status. Omit unpublished-edit labels from the header; retain the existing Publish eligibility rules. Save failures appear in the dismissible editor alert; retry/download actions remain available independently after dismissal, and compact headers omit the failed-save status. Desktop Back to content stays pinned above the canvas title, vertically centered with Outline and Details. A title stays pinned only while it leaves at least a usable writing band below it; unusually tall titles scroll with the canvas. Touch-only compact editors place Back, Outline, Undo, Redo, Commands and Details in one horizontal toolbar above the canvas. Use at least 44px square targets and preserve the existing touch-only and compact-layout eligibility rules. Save status and publication actions remain in the application header; the header scrolls with the document on mobile. The toolbar must stay visible while typing and scrolling with the keyboard open. A CSS sticky slot preserves its space as a sibling of the canvas, never an ancestor of the editor. Keep the toolbar inside BlockNote's scroll container; its native viewport integration owns keyboard geometry and formatting-toolbar clearance.

Docs, Updates and course lessons share the BlockNote writing editor. Keep the desktop workspace's centered text column, title typography, sticky title, Outline and Details composition, and publishing controls. The adapter uses the free BlockNote shadcn package with Fieldbook theme tokens. BlockNote owns its slash menu, block handles, selection toolbar, table selection, clipboard behavior and code editing. Configure its command list to match the supported Fieldbook blocks rather than layering another selection or insertion implementation over it.

Use the stock BlockNote ShadCN Button and Input components and their native size variants; do not substitute application-wide control sizing throughout the editor. Fieldbook supplies fonts, semantic colors, radii and surface elevation through a scoped theme layer, following BlockNote's [CSS theming guidance](https://www.blocknotejs.org/docs/react/styling-theming/overriding-css). Scope menu rules to `.bn-root.bn-shadcn`, since native portals are not necessarily inside the editor container. Keep native ShadCN/Base UI menu components, focus handling and portal targets; the application's Radix primitives are not interchangeable with the installed BlockNote components. Ordinary, submenu and checked menu rows share Fieldbook label typography, padding and rounded hover states. Reserve a right-hand indicator slot with 16px checks and arrows; touch rows retain at least 44px targets. Preserve the configured command menu's grouped descriptive rows, keyboard-shortcut badges and readable width. Explicit control refinements remain scoped to those controls: compact block-side buttons retain touch targets, and table grips retain their configured sizing and border-centered glyphs. Native block content keeps its spacing, indentation and scrolling; only heading typography and explicitly configured code chrome are themed. Keep block-side controls below the pinned title and Back navigation using the supported side-menu controller layer; obscured block tops must not paint controls over those surfaces. Leave other popup layers and native drag behavior unchanged.

Table grips use the native `TableHandle` inside the supported `TableHandlesController` component slot. A scoped Base UI trigger override opens their menus on completed clicks, leaving press-and-drag to BlockNote and suppressing clicks generated after a drag. Keep keyboard activation and touch taps available. Do not apply this override to other editor menus or replace native table movement operations. Add-row/column bars stay thin, with a pointer over the plus icon and the native resize cursor on the rest of the bar.

Code blocks retain BlockNote's native code DOM, node view measurements, content padding, scrolling, plain-content schema, keyboard extensions, HTML parsing/export and Shiki highlighting. A dark header uses BlockNote's ShadCN menu components, portalled into the native renderer's non-editable language host. Do not replace the code node view with a React renderer or add canvas/trailing space for the header. Ignore UI mutations only inside that header; selection, code edits and browser paragraph splits outside it still reach the native editor. Pointer menu use keeps editor focus through BlockNote's supported focus handling; keyboard menu navigation remains available. Use readable text and a matching dark syntax palette. Preserve imported language labels, including unknown labels, without automatic detection or rewriting.

Headings and collapsible headings use BlockNote's native renderer and toggle frame. Their font sizes, weight and line height use the shared authored-heading tokens also consumed by the reader; native heading padding remains intact. Theme the native heading wrapper through block attributes and size variables so its empty placeholder and typed text share metrics. The supported `SideMenuController.floatingUIOptions` follows the themed first-line height, retaining native offsets for other block types. Keep Markdown reader styles off the editing surface. Editable heading text inherits its native wrapper's weight and line height, so application page-heading styles cannot give it different metrics from the empty placeholder. Keep toggle spacing, children and caret behavior native.

Images and uploaded or embedded videos share the native file-panel surface and media placeholders. Use one border and shadow around the panel, without a nested card. Hide tab navigation only when there is one option; retain Upload and Embed when an uploader is available. The embedded-video block uses BlockNote's resizable file wrapper and caption/replace controls with Fieldbook video playback, rather than an inline URL form. Embedded-video commands start on the Embed tab. Image upload and paste use the same native uploader callback.

Mobile writing uses BlockNote's supported single `bn-scroll-container` around the app. BlockNote owns visual-viewport and keyboard geometry; the app's document flow and top toolbar remain inside that container. Formatting uses BlockNote's keyboard toolbar. Do not add a competing viewport-offset or caret controller. Desktop retains its bounded canvas or flowing page layout. Keep native selection handles, accessible menu controls and reduced-motion behavior. Phone keyboard and selection behavior needs physical-device review; desktop viewport emulation cannot establish it.

Content titles remain separate metadata fields visually aligned with the writing column. Return moves into the body through the editor's cursor API. Outline and Details remain Fieldbook panels and return focus to their toggles. They start open only when they clear the text column, close when narrowing first crosses the text, and do not reopen automatically on widening. Desktop panels may remain open together when they fit; compact panels open one at a time.

The authoritative authoring format is a validated `fieldbook-blocks` version 1 document. Its Markdown `body` projection is generated on each save for download, search and compatibility. Legacy Markdown opens through the bounded importer, without a conversion save on opening. Unsupported syntax retains source recovery instead of discarding content. Native blocks render through the static reader without loading the editor. Named authored colors use the shared `--authored-*` tokens in the editor, color-picker swatches and reader; keep text colors distinct and readable while highlight backgrounds remain soft. Preserve draft/published separation, stable block IDs, ready private-media references and course image alternatives. Do not edit a native document's generated Markdown as a second source of truth.

Use BlockNote's native trailing placeholder at its normal size to add the next paragraph. Do not extend the editable area with calculated trailing room, bottom padding or a minimum height; blank canvas space outside the editor belongs to the workspace layout. BlockNote owns ordinary caret visibility, editing scroll behavior and mobile formatting-toolbar clearance. Tables remain horizontally scrollable within the writing column.

The workspace owns normal page scrolling outside mobile editing; mobile editing uses BlockNote's app scroll container. Nested lists may scroll when bounded, but short screens and enlarged text must still reach every control. Do not solve a sizing problem with a global overflow lock. Tables and horizontal strips scroll within their own containers without trapping vertical page scroll.

Expanded category item tables retain native vertical scroll chaining: page scrolling continues when the list fits or reaches either boundary. Keep horizontal containment and the bounded long-list viewport.

Use semantic elements, accessible names, visible focus, and keyboard-operable controls. Check the states and layouts affected by the change, including empty, loading, error, disabled, selected, long-content, and enlarged-text states where relevant. Review desktop, tablet, and phone layouts when the change can affect them. Exercise affected interactions such as filtering, opening menus, and saving.

Mobile Details begins with publication status. Details then orders publishing requirements, short description, organization, Assign, Quiz settings when a course has a quiz, artwork, course duration and version, then Recovery. The quiz passing requirement is edited in Details; the quiz canvas points authors there. Hide publishing guidance when no requirements remain. Short descriptions show a live 300-character count. Details inputs, textareas and picker searches use the metadata control variant to retain the smaller label/copy typography at every width. Other controls retain their default responsive type sizing. Category and section pickers grow through five options, then scroll with subtle edge fades. Draft Courses keep audience assignment visible but disabled until publication; audiences remain optional. Before a Course is first published, Version shows only its current version; republishing controls appear after publication. Recovery holds Markdown download and the published-version restore action. Published Updates retain their optional feed-renewal control.

Docs navigation uses one ordered sibling list for direct Docs and subsections, with a continuous hierarchy line. Dragging to a subsection’s top or bottom edge inserts beside it; dropping in its center moves a Doc into it. Arrow keys and Move up/down use the same mixed order. Keep saved reader navigation and Previous/Next traversal consistent with the admin list.

Placement controls let contributors select existing Docs sections/subsections and Course/Update categories. Only administrators can create or manage those structures. Place contributor guidance beneath the picker, outside the dropdown and visible before opening it: “Ask an administrator to create a new section.” for Docs, or “Ask an administrator to create a new category.” for Courses and Updates. With no destinations, the open dropdown says “An administrator must create a section first.” or “An administrator must create a category first.” Keep “No matching…” for searches when destinations exist. Unfinished drafts may have no destination; publication requires one. Existing categories discovered from content remain selectable before category settings have been saved, without granting contributors creation controls. Saved category lists remain authoritative so stale saves cannot recreate a deleted category.

Uploaded videos use native browser playback controls, including their speed menus; do not add a second speed selector below the player. Native control appearance follows the browser. Images use native BlockNote file controls and captions. Preserve meaningful image descriptions from imported content and use the file name when no authored description is available.

Media upload and clipboard handling use BlockNote's native file blocks, loading feedback and undo behavior. Fieldbook's uploader callback supplies durable media URLs and reports failures through the dismissible editor alert. In views without an uploader, file pastes show “Uploads are unavailable in this view.” without changing the draft; ordinary text and code pastes still use the native handler. Image-only clipboard data in a code block does not start a prose upload. Lazy editor startup reserves a silent busy surface instead of flashing a loading sentence. Do not add temporary loading content to the stored block document or generated Markdown.

BlockNote owns rich-text selection, table-cell selection, keyboard editing, clipboard import and focus inside its menus. Editor toolbar actions use explicit button types so they cannot submit content or settings forms. Opening a menu must not emit a storage conversion merely because native nodes have normalized their defaults. Use its supported editor APIs and component slots rather than keeping app-level selection controllers, nested cell editors or saved-range restoration. Check that formatting, paste and undo retain surrounding text, media and block properties. Native trailing placeholders provide the next writable paragraph without added canvas space.

Categories places its page title and description above the settings card, using the shared page header. Group the pending-change bar directly with that card so their borders meet without a gap. Guidance uses the available card width and wraps only as space requires. Keep separate Course and Update lists. Course categories use the bordered ReorderRow card variant and Docs row spacing; expanding a category extends the same border around its compact item table and controls. Update categories retain flat rows with inset disclosures and horizontal separators. Omit table perimeter borders in both lists. Each list keeps Create category above its category-name search, followed by selection checkboxes and persistent bulk actions for moving contents or deleting categories after relocation. Keep category discovery and selection pinned as one block while the page scrolls, below any active settings-save bar. Use the shared light fade only when category content passes beneath those controls. Expanded categories contain compact item tables with a bounded Search items field on its own row, followed by item and selection counts, Clear selection and Bulk actions. Preserve select-all matching items and individual move menus. Their table headers stay visible within a viewport of about five rows; search and bulk actions remain above that viewport. Use the shared light scroll fades only where more rows are hidden, placing the top fade beneath the sticky heading. The Categories navigation entry uses the tag icon shared with its rows. Center selection controls in their row or cell, and pin item menus at the right when the table scrolls horizontally. Bulk actions remain visible and require at least two selected categories or items; the select-all checkbox does not count as a selected record. Single-item moves stay in each row’s menu. Selected content rows retain a quiet highlight, and long titles wrap within the bounded title column. Renaming retains the category’s expansion and selection and returns focus to its menu; deleting a category clears its selection. Only Course categories expose reordering, with drag, arrow-key and menu controls; clear search before reordering so the full order is visible. Create, rename, move and deletion changes remain staged until Save settings. Empty categories stay available to authors and hidden from readers. Unfinished drafts without a category remain in Content and are omitted from Categories. Categorized drafts remain included in item lists, counts, moves and deletion checks. Keep stale or restored placements available for category repair. Category deletion confirmations describe permanent category removal and content relocation; they do not use the content recovery warning. The UI catalog includes the live category panel with empty and large populated states.

When adding or changing a shared component, show representative states in the demo's `/ui` catalog using the actual component, and document any non-obvious usage or accessibility rules. The catalog uses synthetic content; it does not supply runtime components to the installed interface.

Run `pnpm check:ui` and relevant browser tests for the changed behavior. Review both apps when shared behavior changes.

Before running demo browser tests, build the demo and install the Playwright browser if needed. Available test commands are in `package.json`. Review the resulting screenshots as well as test output. A local browser check does not prove a hosted installation's authentication or data behavior.
