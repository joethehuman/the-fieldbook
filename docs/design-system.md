# Fieldbook design system

Fieldbook's design system is the shared interface code in `components/` and `styles/`, together with the usage rules in this guide. The installed app and separate interactive demo use that code. The demo-only `/ui` catalog shows representative examples, not a complete component inventory or the source of the components.

Its foundations are shadcn/ui source composition, Radix interaction primitives, Tailwind CSS 4, Geist, Lucide, and semantic theme variables. This guide is for contributors changing the interface.

## Where the interface lives

| Layer | Location | Owns |
| --- | --- | --- |
| Theme | styles/tokens.css | Colors, type, spacing, radii, and page measures |
| Primitives | components/ui/ | Controls, fields, dialogs, menus, cards, tables, and feedback |
| Patterns | components/patterns/ | Repeated page composition and navigation |
| Product components | components/ | Reusable feature UI, such as `CourseCard` and `CurriculumCard` |
| Application layout | styles/layout.css | Shell and feature geometry |
| Reading and artwork | styles/content.css and styles/artwork.css | Authored content and decorative media |

Before building a control, card, or page pattern, check the shared components and the `/ui` examples. Reuse or extend an existing component when it already owns the behavior. For example, `CourseCard` and `CurriculumCard` compose the shared `LearningCard`; the demo and installed Updates pages both use `UpdateCard`.

Generated card artwork uses a consistent 1.5rem short title at every browser width. Horizontally scrolling CourseRow strips use a subtle 0.5rem edge fade only where more content is hidden, using the shared header fade’s tapered profile and reaching full transparency at the clipping edge to avoid a hard cutoff.

CourseCard owns the deadline cue in both apps. Overdue assigned courses show “N days past due” in the semantic destructive color; upcoming deadlines and “Due today” use muted text. Completed courses, guests and disabled due dates omit the cue.

Put new reusable controls in `components/ui/`, repeated composition in `components/patterns/`, and reusable product UI in `components/`. Keep route-specific data fetching, permissions, mutations, and route destinations in the owning app or demo feature. A one-off layout can stay local; move it into the shared library when reuse warrants it. Do not copy a reusable interface between the installed app and demo or build a second feature-specific control system. Avoid broad overrides and components with options for every possible layout.

## Compose a page

- Use SectionHeader for a section's title, description, and actions. Use CollectionControls or CollectionToolbar for search, sort, filters, and creation actions. The compact Admin section picker uses the same visible groups and headings as the desktop sidebar: Publishing, People & Progress, and Organization Settings. Group labels are muted, non-selectable headings; existing role filtering and destination behavior remain shared.
- Use a consistent heading action area for Admin collection creation; pinned hierarchy controls keep their creation action within the sticky area. At narrow admin content widths, search takes a full row and labeled filters and sort choices share the next row. Keep essential names readable and multi-column reports horizontally scrollable. On narrow Admin layouts, place hierarchy counts on the second row, left aligned with the visible selection checkbox; preserve their vertical alignment with row menus and the checkbox’s larger touch target. Settings forms retain their section grouping with smaller insets. These composition rules follow available space; touch sizing also covers hybrid inputs and portaled admin menus and dialogs, independently of the writing editor's input rules.
- Use Field, FieldDescription, and FieldGroup for forms. Associate help and errors with controls, mark invalid fields, and keep labels visible. FieldError aligns its message and dismiss button vertically, including when the message wraps.
- Use Button for commands; use an actual link for navigation. Use Tabs for panels, FilterOptions for collection filters, SortPicker for ordering, and DropdownMenu for actions. Text commands, including ghost buttons with icons, retain Button’s shared horizontal padding. Align them through their surrounding layout rather than stripping padding from their hover or disabled surface. Zero-padding exceptions belong to inline links, icon-only controls or specialized patterns with their own geometry.
- Teams use a chart at wider widths and a searchable, paginated directory on phones. Phone selection controls are immediately available; Select multiple switches the wider chart to a selectable table. Team and group directories preserve search, filters, sorting, pagination, valid row selections, and scroll position while opening details and returning through browser history or the in-app return control. Return focus to the directory heading without moving its restored scroll position. Entering another administration section or starting a new session starts fresh; accepted detail navigation clears transient detail forms. Completed actions clear their selection, and unavailable records are excluded from action targets.
- Use DataTable with a declared column schema for application records. Keep horizontal overflow inside TableContainer. Plain tables remain appropriate for authored content.
- Authored tables use GFM Markdown plus an optional versioned width comment at the start of the body. Width entries follow top-level tables in order; tables inside quotes retain automatic sizing without Fieldbook resize or drag handles. Plain Markdown tables without saved widths also retain automatic sizing. Table cells support text, links and inline formatting. Text selection stays within a cell until a mouse drag crosses into another cell; crossing selects complete cells as a rectangle. The Copy table action copies the complete grid with inline formatting and saved column layout, including recent cell edits; selected cells support copy, cut, paste and keyboard extension. Clipboard HTML is parsed as data and rebuilt from supported inline content. Cell ranges use the shared soft selection fill with the table grid visible; an individually active cell uses the blue focus outline. Suppress the active-cell outline while a cell range is selected. Row and column control targets stay outside cell content, with the table action menu above the row-control gutter. Block insertion commands and image-file paste are unavailable inside cells; insert images, videos, code, dividers and tables in the surrounding canvas. Existing inline images in authored table Markdown are preserved. Tables keep their natural or saved width instead of stretching to the text width. Wider tables scroll within the writing or reading area, with edge fades where more columns are hidden. Inserted tables, media, images, code blocks, and dividers place their action menu in the left writing gutter; the menu stays outside a table's horizontal scroller. Editor resize tabs use grab and grabbing cursor feedback, and resizing one column preserves the others' widths. Direct expansion stops at 640 pixels; a naturally wider column retains its width when another is resized and can be reduced gradually. Keep table width changes in the content field so draft, publication, and Markdown export carry the same layout.
- Content feedback starts a new entry for each interaction. A thumb saves immediately; its optional comment updates that entry. Successful submission or dismissal resets the form. Administrator feedback uses compact single-line table rows with bounded content titles with inline versions (omitted for general feedback), a shared title tooltip only when the text is truncated, an 80-character comment excerpt, an accessible comment icon opening the full-comment dialog, and a pinned action menu. Rating-summary pills toggle the table rating filter; their counts and percentage reflect the current content and search scope, so both rating counts remain available while switching. The content filter uses a searchable picker; the collection search matches content titles and comments. Keep the search query in its field rather than duplicating it as an applied-filter chip; keep the result toolbar and selection column stable as matching counts change. Feedback deletion uses the shared individual and bulk action controls with permanent-delete confirmation.
- Fenced code blocks share a muted surface, language header, syntax colors and Copy action across writing and reading. New blocks default to Auto-detect; authors can select a supported language or Plain text. Unlabeled Markdown remains unlabeled when exported, so detection never rewrites content. Explicit and unsupported language labels are preserved; unsupported or uncertain code displays as plain text. Copy preserves code indentation and line endings, confirms success and offers a dismissible manual-copy message on failure. The code area grows to 24rem before scrolling vertically; long lines scroll horizontally without wrapping. The header and gutter actions remain outside the code scroller. Keep inline code separate from fenced blocks and keep detection local to the browser.
- Use shared dialog and picker patterns. Keep search and actions reachable while result lists scroll. Preserve keyboard selection, dismissal, and focus return. Assignment selection uses a tall Available / Assigned transfer dialog: each pane has its own search and section headings that stay pinned until the next section replaces them, with matching included teams shown in their source hierarchy; direct Add/Remove actions update sources, and expanded sources explain included team branches. Audience rows keep the group or team icon, name, compact people/team metrics and action on one line. Long names truncate while retaining their full accessible labels; guest and inherited-source details use labeled inline icons. Team-count chevrons expand branches without shifting the leading icon, and disclosures reflect their open state. Direct assignments have their own heading above Through curricula. Only top-level sources appear initially; overlapping coverage may appear under each source. Included child rows have disabled Remove controls; saved direct links stay intact and can be managed within the source disclosure. Curriculum sources remain visible and cannot be removed from a course. Multi-item additions retain existing assignments and label pending choices To add. On phones, show one full-height pane with Available / Assigned controls rather than stacking lists. Use native lists and buttons, announce transfers, and retain focus after a row moves; these rows are not ARIA listbox options. Course and curriculum pickers opened from groups or teams use one Manage Courses action and the searchable Available / Assigned transfer layout. Saved direct links load on the right; additions and removals save together. Curricula expand to show included courses with disabled individual removal. Bulk management labels partial assignments and preserves them unless the administrator removes them or assigns the item to all selected audiences. Updates use the audience picker in their editor, and the compact transfer for live group recommendations from content and group pages; Manage Updates shows current group recommendations under Assigned and saves additions and removals together, preserving untouched partial recommendations in bulk management. Updates are recommendations without a completion requirement. Group and team row, bulk and detail menus expose the same course actions. Curricula expose one Manage Audience action for individual and bulk selections; it loads current team/group links and saves additions and removals together, retaining untouched partial links for bulk selections. Group menus also manage live Update recommendations; team Update targeting is managed in the Update editor. Leave space around picker searches for the complete focus ring.
- Use the shared publication, progress, empty, error, loading, and pending-save states. Publication state and draft-save state remain separate. Content listings show newer draft edits; editor headers keep publication badges and use Publish eligibility for pending changes.
- Failure and unavailable-action messages must be dismissible. Use Alert for operation failures; destructive alerts and alerts with `role="alert"` include a close control. Other failure notices opt in with `dismissible`. Dismissal hides notification copy without changing permissions, validation, unsaved work or recovery state. Keep necessary retry/recovery controls outside the message. Clear transient notification copy with `onDismiss`, or use `dismissKey` for a new attempt with the same message. Keep copy short: the reason, next action and reference ID when available. Focused messages have no outline; their controls use a neutral focus indicator. The shared transition animates occupied space and respects reduced motion.
- For explicit manual saves, compare the draft with its saved baseline in the owning form and use SaveChangesControl. Keep Save visible but disabled when nothing changed. In settings footers, keep the gray save area compact and place a quiet Discard action just below it when editing begins. Announce unsaved and saving states to assistive technology without adding visible status text; explain any other reason that blocks saving. Guard form submission as well, so pressing Enter cannot save an unchanged draft. Automatic draft saves and publication actions have their own states.

A parent layout owns the space between sections. A field group owns the space between fields. Individual controls should not add compensating margins. Use semantic theme tokens rather than literal interface colors; decorative artwork and validated runtime branding are separate cases. Text must remain readable when it wraps or grows.

## Layout and accessibility

The shared app header centers the search field horizontally over the workspace and vertically with the installation name and sidebar toggle. If the centered field would overlap editor publication controls, search alone switches to its icon and full-width panel. This measured fit rule does not change the navigation or editor breakpoints. Search panels close when their presentation changes, preserving the query. The search clear icon sits inside the field with reserved text padding, keeping the field width stable as authors type. A consistent page inset adds breathing room below search and visually aligns page headings with the first primary sidebar item. Top-right breadcrumbs are omitted; the sidebar, account menu and contextual Back actions provide navigation. Narrow Docs place the title area before the On this page disclosure; wide Docs retain the outline beside the article. The shared app header fades its bottom edge only when workspace content has scrolled beneath it. Header and pinned-title fades share a short, light transition; keep them non-interactive and leave the unscrolled edge clear. Content editors put save status and publication actions in the shared app header. Compact navigation uses a muted spinner while saving/uploading and a check only after a confirmed save, centered in a fixed icon area alongside the publication badge and button. New unsaved drafts leave the icon area empty. Screen readers receive the live save status. Omit unpublished-edit labels from the header; retain the existing Publish eligibility rules. Save failures appear in the dismissible editor alert; retry/download actions remain available independently after dismissal, and compact headers omit the failed-save status. Desktop Back to content stays pinned above the canvas title, vertically centered with Outline and Details. A title stays pinned only while it leaves at least a usable writing band below it; unusually tall titles scroll with the canvas. Touch-only compact editors omit Back to content and place Outline, Undo, Redo, Commands and Details permanently in the app header. Keep the existing rounded card, with 30px-wide and 44px-high controls inside a 46px surface. Give it a real header grid slot between Search and publication controls; focus and keyboard changes never relocate or fade the card. Reserve a fixed 20px slot for the saving/uploading spinner and confirmed-save check beside Publish. Below 360px, retain the live save announcement without the visual icon. Mobile Draft/Published status belongs in Details. Save failures remain in the editor alert. Search and navigation can hide the dock without changing header height.

Mobile editing uses one application boundary with a normal-flow header, an alert row and a bounded canvas row. The canvas and its overlay host share that row. One `.main-content` scroller owns vertical document movement; titles, course introduction, lessons, prose and Quiz flow within it. A single browser adapter places the complete touch editor at the visual viewport's reported origin and size, including landscape and attached-pointer layouts. The header and canvas remain together; do not position or transform the header independently. The body stays fixed, navigation is relative to the app, and body-portaled dialogs use the same viewport origin and available size. Native input reveal can pan the visual viewport even when document scroll is zero; do not fight that pan with root scroll resets. Viewport events apply the complete rectangle together without changing native selection. Before a height decrease at the same width, capture a collapsed prose caret only when it is visible in the existing canvas. After layout, the shared writing owner may minimally reveal that same target once; leave native corrections, manual scrolling and selections in control. Release this resize transaction immediately, and ignore growth, origin-only panning, width changes and zoom. Focus and page restoration coalesce later geometry reads. Retain the last unzoomed rectangle during pinch zoom, leave intentional zoom and panning native, and release all viewport sizing and placement when leaving touch editing. Keep mobile page layout stable through title and keyboard changes; desktop layout heuristics run only outside the mobile mode. Changing input capabilities or orientation preserves the editor instance, native selection and painted writing position.

Native editing and Lexical own ordinary typing, wrapping, Return, caret movement and selection. Programmatic transitions from titles, blank canvas, guided navigation or a popup into prose focus the native editor with `preventScroll` before committing its Lexical selection; native selection can otherwise focus it implicitly before any protected focus call. Explicit blank-canvas returns use the same bounded reveal as other writing returns. Do not add a second continuous caret controller or blanket skip-scroll policy. Preserve targeted skip tags for popup selection bookkeeping and other transactions that must not scroll while a menu owns focus. Keep intrinsic mobile contenteditable height, one modest end reserve and blank-canvas tap-to-write behavior; avoid artificial minimum-height tails and stacked keyboard padding. Code and Markdown source retain their genuine internal scrollports. Native selection and intentional scrolling keep control. Typed slash queries use the same bounded reveal while their virtual input retains its exact native target; literal fallback and empty-query cancellation return explicitly to writing. An explicit popup return restores a valid saved target in the user gesture and may minimally reveal that same native focus edge through the resulting canvas resize. This return session ends on the next input, key, pointer, touch, wheel, blur, handoff, capability change or target mismatch; it never changes selection or follows viewport panning. Ordinary edits do not acquire that session. Field returns restore their selection before native focus. Publishing requirements, lesson navigation and other deliberate actions retain their bounded target reveal.

Mobile Commands, media, Outline and Details use the shared canvas overlay host, with one CSS anchor beneath the header and their existing widths and appearance. Available height follows the canvas row; geometry never refocuses a menu or changes its anchor. Keep Commands roomy with an internally scrolling list and reachable close action. Fields and long panel content scroll within their own surface. Search retains its header host and measures against the same bounded shell. Commands requires a current prose caret or selection; title and metadata focus cannot reuse an old selection. Outline/Details and writing popups are mutually exclusive. Opening an insertion menu preserves its target and a temporary visible text highlight where CSS custom highlights are supported, without changing document markup or native handles. Remove that paint on return, dismissal or invalidation. Closing with the toggle, Cancel or Escape restores writing focus synchronously; discard stale targets when their field or document changes. Commands to media retains the insertion target without briefly reopening prose input. Typed slash suggestions remain immediate and survive native caret scrolling; deliberate scrolling dismisses them. Touch-only devices retain native selection controls; desktop contextual formatting remains unchanged. Respect reduced motion. Desktop placement, balanced canvas gutters and the existing compact-layout cutoff remain unchanged. The writing surface is borderless, with a pinned document title or current lesson heading. Desktop authors insert blocks with the slash menu and format selected text with contextual controls. Desktop navigation retains one vertically centered row. The reading column narrows only as needed to preserve minimum clearance for the edge buttons, a small gap and the Back button padding; Back stays aligned with the canvas titles. This applies with an expanded sidebar and enlarged text. Back remains visible on desktop even when search independently switches to its icon. App navigation has one compact mode, which also switches search to its icon: phone widths below 768px, or portrait touch tablets below 1280px. Other viewports retain the desktop sidebar and search field. Switching navigation layouts restores the saved desktop sidebar width immediately; animate only deliberate sidebar toggles. Compact authors use the existing app navigation and account menu to leave the editor. Commands and undo/redo appear in the thin floating toolbar only at phone widths or on portrait touch tablets with no reported mouse or trackpad; mouse and trackpad editors retain desktop Back, Outline and Details at every viewport width, with slash insertion and contextual formatting instead of a persistent writing toolbar. Narrow desktop panels are constrained to the available canvas width. Compact layouts use a search button that opens a full-width field. Switching between the search field and icon closes the panel while preserving the query. Markdown download lives in Details and exports the active document or lesson. Below Recovery, a divider precedes the red Delete Doc, Delete Course or Delete Update button. It uses the content list’s existing deletion confirmation and 30-day recovery warning. Deletion waits for saved edits and completed uploads; a failed deletion keeps the editor open. Canvas titles use a compact inset below desktop navigation or the compact app header. Course and lesson headings keep a modest gap; the lesson eyebrow sits close to its title. Lesson titles use 28px type with 36px leading, subordinate to the 32px course title. The course title scrolls above the lesson or Quiz heading. Quiz shares the lesson title typography and pinned behavior; its outline actions contain only Delete quiz. Question delete controls appear only with multiple questions, and answer delete controls only above two answers. Removal handlers retain these minimums. The selected outline lesson keeps one actions menu beside its title for reordering, duplication and removal. Every lesson reserves the same action space so titles keep their width, and hover covers the entire row. Lesson menus open beyond the outline surface to its right when space allows; narrow overlay layouts keep menus within the viewport. Outline and Details share the same floating surface at the outer workspace edges, with a width of 320px, constrained only when the viewport is smaller. Entering a content editor collapses the main sidebar, which authors can reopen with its toggle. The text column stays centered at the reading width, narrows fluidly on smaller screens and uses balanced side padding. Compact canvases reserve equal 44px block-action gutters on both sides, keeping Back, titles and writing aligned on a centered column. The compact dock retains 44px-high targets and equal space around its controls. Non-text blocks reserve space before the next writing line. Inserting a divider or code block consumes only the command line or prefix emptied by the insertion, preserves authored neighboring blanks, and reuses an available following line. Arrow keys at a code block’s start or end return focus to the adjacent writing line; ordinary arrows continue navigating within code. Native selection updates preserve keyboard focus in an open Commands or media menu; applying or dismissing the menu explicitly returns to writing. Use block display for their decorators to avoid anonymous inline line boxes; keep the same gap when media is followed by text in its paragraph. Standalone videos use block nodes while videos within text keep their inline representation; both export the same ordinary Markdown media links. Lists insert native empty list items immediately so marker style, indent and caret geometry remain stable through typing, pasting and composition. Block menus stay just outside each element’s top-left corner and remain visible in compact mode; tables keep their row/column control space rather than moving the block menu above the table. Menu toggles never change the column width or position. Menus use the surrounding space when it fits and otherwise overlay the canvas. Keep their headings fixed and scroll only the body, with subtle content-edge fades that preserve the card border, shadow and bottom padding. Docs and Updates start with Details open, and Courses with Outline open, only when the preferred menu clears the text column. Otherwise menus start closed. Narrowing closes an open menu when it first crosses into the text; authors can deliberately reopen it as an overlay. Widening does not automatically reopen menus. Touch dock menus overlay the canvas inside the usable band without changing its width or overlapping the dock. Desktop menus may stay open together when they fit; compact menus always open one at a time. Their external toggle remains the close control. Mouse layouts return focus to that toggle; touch dock menus restore the saved writing target. A restored text selection reveals its focus edge inside the usable band while retaining the selection; manual selection dragging keeps control. Moving from Commands to a media chooser retains the insertion target without briefly reopening prose input. Publishing requirements smoothly reveal their target, respecting reduced motion: titles receive a spacious attention outline only for guided publishing navigation, empty writing canvases receive a caret on their first line, and quiz requirements reveal the question section without selecting an individual field. Direct title clicks and ordinary keyboard focus stay borderless; a deliberate click or blur clears the publishing highlight without moving the text. Keep the native title field square so it does not round or clip the caret and text selection; rounding belongs to the separate attention outline. Measure title growth and shrinking in an inert copy without temporarily collapsing the focused field.

Desktop content canvases keep blank space below the final block equal to about 30% of the usable writing area. Place this physical reserve inside the top-level writing content and size it from the active canvas or page scroller. Existing blank room in a short canvas counts toward the reserve. Keep the space stable through focus and menu changes, preserve the writing position as the layout changes, and retain the current automatic scrolling behavior. The reserve is interface layout and is never saved as content. Touch-only editors keep an intrinsic 8px end inset; the desktop comfort allowance does not add to it.

Pasting a web address over selected prose applies a link while preserving its wording and inline formatting, including in table cells. Recognizable bare domains use HTTPS. Link paste is one undoable edit; ordinary text, code and media pastes retain their existing behavior.

The workspace owns normal page scrolling. Nested lists may scroll when bounded, but short screens and enlarged text must still reach every control. Do not solve a sizing problem with a global overflow lock. Tables and horizontal strips scroll within their own containers without trapping vertical page scroll.

Expanded category item tables retain native vertical scroll chaining: page scrolling continues when the list fits or reaches either boundary. Keep horizontal containment and the bounded long-list viewport.

Use semantic elements, accessible names, visible focus, and keyboard-operable controls. Check the states and layouts affected by the change, including empty, loading, error, disabled, selected, long-content, and enlarged-text states where relevant. Review desktop, tablet, and phone layouts when the change can affect them. Exercise affected interactions such as filtering, opening menus, and saving.

Mobile Details begins with publication status. Details then orders publishing requirements, short description, organization, Assign, Quiz settings when a course has a quiz, artwork, course duration and version, then Recovery. The quiz passing requirement is edited in Details; the quiz canvas points authors there. Hide publishing guidance when no requirements remain. Short descriptions show a live 300-character count. Details inputs, textareas and picker searches use the metadata control variant to retain the smaller label/copy typography at every width. Other controls retain their default responsive type sizing. Category and section pickers grow through five options, then scroll with subtle edge fades. Draft Courses keep audience assignment visible but disabled until publication; audiences remain optional. Before a Course is first published, Version shows only its current version; republishing controls appear after publication. Recovery holds Markdown download and the published-version restore action. Published Updates retain their optional feed-renewal control.

Placement controls let contributors select existing Docs sections/subsections and Course/Update categories. Only administrators can create or manage those structures. Place contributor guidance beneath the picker, outside the dropdown and visible before opening it: “Ask an administrator to create a new section.” for Docs, or “Ask an administrator to create a new category.” for Courses and Updates. With no destinations, the open dropdown says “An administrator must create a section first.” or “An administrator must create a category first.” Keep “No matching…” for searches when destinations exist. Unfinished drafts may have no destination; publication requires one. Existing categories discovered from content remain selectable before category settings have been saved, without granting contributors creation controls. Saved category lists remain authoritative so stale saves cannot recreate a deleted category.

Uploaded videos use native browser playback controls, including their speed menus; do not add a second speed selector below the player. Native control appearance follows the browser. Image uploads offer an optional Alt text field without blocking file selection; omitted text retains the filename fallback, and authors can edit it later. Meaningful descriptions remain useful for informative images.

Pasted images and command-uploaded images or videos use the same quiet muted Loading… bar with a small spinner at the insertion point, then replace it with the media. The spinner respects reduced motion and never changes the bar height. Keep upload feedback out of the space above the editor so navigation and pinned titles do not move. Loading blocks are temporary editor state and never saved in Markdown; an upload failure restores the original text and retains the existing error and retry behavior. The image-fetch placeholder uses the same bar instead of a dashed image icon. Lazy editor startup reserves a silent busy surface instead of flashing a loading sentence. Disabled contextual navigation stays transparent during upload; normal hover and focus cues return when navigation is available. Image-only paragraphs hide their managed caret line inside the block wrapper while retaining normal spacing below the block. Restore the caret to the first following writing line after upload releases read-only mode; reuse existing lines and preserve intentional blanks.

Text selections exclude adjoining blocks when their endpoints contain none of those blocks’ content, for deletion, replacement, copying, and formatting. Clipboard import drops empty trailing styled-block artifacts and preserves the original style of untouched text after a rich-text paste; meaningful pasted headings retain their formatting. Deliberate paragraph joins and selections that include actual text in the next block keep normal editing behavior. Contextual formatting targets the editor owning the native selection, including table cells, and refreshes its target when switching editors. Escape dismisses formatting tools and returns to that writing target without blurring the canvas.

Media-only paragraphs contain content even without text. Inserting or formatting adjacent blocks must preserve the media and existing heading styles; heading formatting across prose leaves media-only paragraphs unchanged. A document ending in media retains a writable paragraph below it, including media inside a list or callout. Nested media uses the same spacing as standalone media without an extra caret line inside its wrapper. Multiple pasted images retain clipboard order, share one undo step, and restore the original document if an upload fails. Editing commands use the current native selection, preserving its direction, before applying block-boundary rules.

## Verify interface work

Categories places its page title and description above the settings card, using the shared page header. Group the pending-change bar directly with that card so their borders meet without a gap. Guidance uses the available card width and wraps only as space requires. Keep separate Course and Update lists. Course categories use the bordered ReorderRow card variant and Docs row spacing; expanding a category extends the same border around its compact item table and controls. Update categories retain flat rows with inset disclosures and horizontal separators. Omit table perimeter borders in both lists. Each list keeps Create category above its category-name search, followed by selection checkboxes and persistent bulk actions for moving contents or deleting categories after relocation. Keep category discovery and selection pinned as one block while the page scrolls, below any active settings-save bar. Use the shared light fade only when category content passes beneath those controls. Expanded categories contain compact item tables with a bounded Search items field on its own row, followed by item and selection counts, Clear selection and Bulk actions. Preserve select-all matching items and individual move menus. Their table headers stay visible within a viewport of about five rows; search and bulk actions remain above that viewport. Use the shared light scroll fades only where more rows are hidden, placing the top fade beneath the sticky heading. The Categories navigation entry uses the tag icon shared with its rows. Center selection controls in their row or cell, and pin item menus at the right when the table scrolls horizontally. Bulk actions remain visible and require at least two selected categories or items; the select-all checkbox does not count as a selected record. Single-item moves stay in each row’s menu. Selected content rows retain a quiet highlight, and long titles wrap within the bounded title column. Renaming retains the category’s expansion and selection and returns focus to its menu; deleting a category clears its selection. Only Course categories expose reordering, with drag, arrow-key and menu controls; clear search before reordering so the full order is visible. Create, rename, move and deletion changes remain staged until Save settings. Empty categories stay available to authors and hidden from readers. Unfinished drafts without a category remain in Content and are omitted from Categories. Categorized drafts remain included in item lists, counts, moves and deletion checks. Keep stale or restored placements available for category repair. Category deletion confirmations describe permanent category removal and content relocation; they do not use the content recovery warning. The UI catalog includes the live category panel with empty and large populated states.

When adding or changing a shared component, show representative states in the demo's `/ui` catalog using the actual component, and document any non-obvious usage or accessibility rules. The catalog uses synthetic content; it does not supply runtime components to the installed interface.

Run `pnpm check:ui` and relevant browser tests for the changed behavior. Review both apps when shared behavior changes.

Before running demo browser tests, build the demo and install the Playwright browser if needed. Available test commands are in `package.json`. Review the resulting screenshots as well as test output. A local browser check does not prove a hosted installation's authentication or data behavior.
