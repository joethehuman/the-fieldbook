# Fieldbook design system

Fieldbook's design system is the shared interface code in `components/` and `styles/`, together with the usage rules in this guide. The installed app and separate interactive demo use that code. The demo-only `/ui` catalog shows representative examples, not a complete component inventory or the source of the components.

Its foundations are shadcn/ui source composition, Radix interaction primitives, Tailwind CSS 4, Geist, Lucide, and semantic theme variables. This guide is for contributors changing the interface.

## Where the interface lives

| Layer | Location | Owns |
| --- | --- | --- |
| Theme | styles/tokens.css | Colors, type, spacing, radii, and page measures |
| Primitives | components/ui/ | Controls, fields, dialogs, menus, cards, tables, and feedback |
| Patterns | components/patterns/ | Repeated page composition and navigation |
| Product components | components/ | Reusable feature UI, such as `CourseCard` and `CurriculumCard` |
| Application layout | styles/layout.css | Shell and feature geometry |
| Reading and artwork | styles/content.css and styles/artwork.css | Authored content and decorative media |

Before building a control, card, or page pattern, check the shared components and the `/ui` examples. Reuse or extend an existing component when it already owns the behavior. For example, `CourseCard` and `CurriculumCard` compose the shared `LearningCard`; the demo and installed Updates pages both use `UpdateCard`.

Generated card artwork uses a consistent 1.5rem short title at every browser width. Horizontally scrolling CourseRow strips use a subtle 0.5rem edge fade only where more content is hidden, using the shared header fade’s tapered profile and reaching full transparency at the clipping edge to avoid a hard cutoff.

CourseCard owns the deadline cue in both apps. Overdue assigned courses show “N days past due” in the semantic destructive color; upcoming deadlines and “Due today” use muted text. Completed courses, guests and disabled due dates omit the cue.

Put new reusable controls in `components/ui/`, repeated composition in `components/patterns/`, and reusable product UI in `components/`. Keep route-specific data fetching, permissions, mutations, and route destinations in the owning app or demo feature. A one-off layout can stay local; move it into the shared library when reuse warrants it. Do not copy a reusable interface between the installed app and demo or build a second feature-specific control system. Avoid broad overrides and components with options for every possible layout.

## Compose a page

- Use SectionHeader for a section's title, description, and actions. Use CollectionControls or CollectionToolbar for search, sort, filters, and creation actions. The compact Admin section picker uses the same visible groups and headings as the desktop sidebar: Publishing, People & Progress, and Organization Settings. Group labels are muted, non-selectable headings; existing role filtering and destination behavior remain shared.
- Use Field, FieldDescription, and FieldGroup for forms. Associate help and errors with controls, mark invalid fields, and keep labels visible.
- Use Button for commands; use an actual link for navigation. Use Tabs for panels, FilterOptions for collection filters, SortPicker for ordering, and DropdownMenu for actions. Text commands, including ghost buttons with icons, retain Button’s shared horizontal padding. Align them through their surrounding layout rather than stripping padding from their hover or disabled surface. Zero-padding exceptions belong to inline links, icon-only controls or specialized patterns with their own geometry.
- Use DataTable with a declared column schema for application records. Keep horizontal overflow inside TableContainer. Plain tables remain appropriate for authored content.
- Authored tables use GFM Markdown plus an optional versioned width comment at the start of the body. Width entries follow top-level tables in order; tables inside quotes retain automatic sizing without Fieldbook resize or drag handles. Plain Markdown tables without saved widths also retain automatic sizing. Tables keep their natural or saved width instead of stretching to the text width. Wider tables scroll within the writing or reading area, with edge fades where more columns are hidden. Inserted tables, media, images, code blocks, and dividers place their action menu in the left writing gutter; the menu stays outside a table's horizontal scroller. Editor resize tabs use grab and grabbing cursor feedback, and resizing one column preserves the others' widths. Direct expansion stops at 640 pixels; a naturally wider column retains its width when another is resized and can be reduced gradually. Keep table width changes in the content field so draft, publication, and Markdown export carry the same layout.
- Content feedback starts a new entry for each interaction. A thumb saves immediately; its optional comment updates that entry. Successful submission or dismissal resets the form. Administrator feedback uses compact single-line table rows with bounded content titles with inline versions (omitted for general feedback), a shared title tooltip only when the text is truncated, an 80-character comment excerpt, an accessible comment icon opening the full-comment dialog, and a pinned action menu. Rating-summary pills toggle the table rating filter; their counts and percentage reflect the current content and search scope, so both rating counts remain available while switching. The content filter uses a searchable picker; the collection search matches content titles and comments. Keep the search query in its field rather than duplicating it as an applied-filter chip; keep the result toolbar and selection column stable as matching counts change. Feedback deletion uses the shared individual and bulk action controls with permanent-delete confirmation.
- Fenced code blocks share a muted surface, language header, syntax colors and Copy action across writing and reading. New blocks default to Auto-detect; authors can select a supported language or Plain text. Unlabeled Markdown remains unlabeled when exported, so detection never rewrites content. Explicit and unsupported language labels are preserved; unsupported or uncertain code displays as plain text. Copy preserves code indentation and line endings, confirms success and offers a dismissible manual-copy message on failure. The code area grows to 24rem before scrolling vertically; long lines scroll horizontally without wrapping. The header and gutter actions remain outside the code scroller. Keep inline code separate from fenced blocks and keep detection local to the browser.
- Use shared dialog and picker patterns. Keep search and actions reachable while result lists scroll. Preserve keyboard selection, dismissal, and focus return. Assignment selection uses a tall Available / Assigned transfer dialog: each pane has its own search and section headings that stay pinned until the next section replaces them, with matching included teams shown in their source hierarchy; direct Add/Remove actions update sources, and expanded sources explain included team branches. Audience rows keep the group or team icon, name, compact people/team metrics and action on one line. Long names truncate while retaining their full accessible labels; guest and inherited-source details use labeled inline icons. Team-count chevrons expand branches without shifting the leading icon, and disclosures reflect their open state. Direct assignments have their own heading above Through curricula. Only top-level sources appear initially; overlapping coverage may appear under each source. Included child rows have disabled Remove controls; saved direct links stay intact and can be managed within the source disclosure. Curriculum sources remain visible and cannot be removed from a course. Multi-item additions retain existing assignments and label pending choices To add. On phones, show one full-height pane with Available / Assigned controls rather than stacking lists. Use native lists and buttons, announce transfers, and retain focus after a row moves; these rows are not ARIA listbox options. Course and curriculum pickers opened from groups or teams use one Manage Courses action and the searchable Available / Assigned transfer layout. Saved direct links load on the right; additions and removals save together. Curricula expand to show included courses with disabled individual removal. Bulk management labels partial assignments and preserves them unless the administrator removes them or assigns the item to all selected audiences. Updates use the audience picker in their editor, and the compact transfer for live group recommendations from content and group pages; Manage Updates shows current group recommendations under Assigned and saves additions and removals together, preserving untouched partial recommendations in bulk management. Updates are recommendations without a completion requirement. Group and team row, bulk and detail menus expose the same course actions. Curricula expose one Manage Audience action for individual and bulk selections; it loads current team/group links and saves additions and removals together, retaining untouched partial links for bulk selections. Group menus also manage live Update recommendations; team Update targeting is managed in the Update editor. Leave space around picker searches for the complete focus ring.
- Use the shared publication, progress, empty, error, loading, and pending-save states. Publication state and draft-save state remain separate. Content listings show newer draft edits; editor headers keep publication badges and use Publish eligibility for pending changes.
- Failure and unavailable-action messages must be dismissible. Use Alert for operation failures; destructive alerts and alerts with `role="alert"` include a close control. Other failure notices opt in with `dismissible`. Dismissal hides notification copy without changing permissions, validation, unsaved work or recovery state. Keep necessary retry/recovery controls outside the message. Clear transient notification copy with `onDismiss`, or use `dismissKey` for a new attempt with the same message. Keep copy short: the reason, next action and reference ID when available. Focused messages have no outline; their controls use a neutral focus indicator. The shared transition animates occupied space and respects reduced motion.
- For explicit manual saves, compare the draft with its saved baseline in the owning form and use SaveChangesControl. Keep Save visible but disabled when nothing changed. In settings footers, keep the gray save area compact and place a quiet Discard action just below it when editing begins. Announce unsaved and saving states to assistive technology without adding visible status text; explain any other reason that blocks saving. Guard form submission as well, so pressing Enter cannot save an unchanged draft. Automatic draft saves and publication actions have their own states.

A parent layout owns the space between sections. A field group owns the space between fields. Individual controls should not add compensating margins. Use semantic theme tokens rather than literal interface colors; decorative artwork and validated runtime branding are separate cases. Text must remain readable when it wraps or grows.

## Layout and accessibility

The shared app header centers the search field horizontally over the workspace and vertically with the installation name and sidebar toggle. If the centered field would overlap editor publication controls, search alone switches to its icon and full-width panel. This measured fit rule does not change the navigation or editor breakpoints. Search panels close when their presentation changes, preserving the query. The search clear icon sits inside the field with reserved text padding, keeping the field width stable as authors type. A consistent page inset adds breathing room below search and visually aligns page headings with the first primary sidebar item. Top-right breadcrumbs are omitted; the sidebar, account menu and contextual Back actions provide navigation. Narrow Docs place the title area before the On this page disclosure; wide Docs retain the outline beside the article. The shared app header fades its bottom edge only when workspace content has scrolled beneath it. Header and pinned-title fades share a short, light transition; keep them non-interactive and leave the unscrolled edge clear. Content editors put save status and publication actions in the shared app header. Compact navigation uses a muted spinner while saving/uploading and a check only after a confirmed save, centered in a fixed icon area alongside the publication badge and button. New unsaved drafts leave the icon area empty. Screen readers receive the live save status. Omit unpublished-edit labels from the header; retain the existing Publish eligibility rules. Save failures appear in the dismissible editor alert; retry/download actions remain available independently after dismissal, and compact headers omit the failed-save status. Desktop Back to content stays pinned above the canvas title, vertically centered with Outline and Details. Touch-only compact editors omit Back to content and place Outline, Undo, Redo, Commands and Details in a thin centered floating toolbar. The floating card keeps one compact size in both positions: at the bottom with the software keyboard closed, and inside the app header between Search and Publish with it open. Reserve its real width in the header; hide the visible save/publication metadata only when the complete row cannot fit, while retaining live save announcements. The app header owns the normal scroll and hit-test boundary, with its canvas-colored background and soft fade; the card has its own border and shadow. Do not add a second top canvas reserve or clip for the dock. The course title scrolls away behind the header. Keep the lesson or document title pinned below it when space permits; let that title scroll normally when pinning would crowd out the active line, and restore pinning with a threshold buffer when space returns. Preserve the existing page scroller and writing position through dock transitions. Fade the dock briefly between positions, follow native viewport movement directly, and avoid a separate chasing animation. Keep typing inside the measured band below the app header and above native controls, or above the bottom dock. Intentional touch scrolling and selection drags retain control through momentum. Touch command and media menus keep one placement mode for each opening. Tap-opened menus appear at their usable height after keyboard dismissal and the bottom dock settles, with a bounded fallback when viewport events are unavailable; typed slash suggestions remain immediate. Inputs in an already open panel or media chooser can reopen the keyboard: move the dock to the top and keep the focused field in the panel's own scroll region beneath it. Menus focus their initial control once and keep that focus as geometry changes. The dock retains its keyboard-free height reference through menu transitions so its native-control clearance survives a return to writing. Respect reduced-motion preferences. Keep compact dock buttons 30px wide and 44px high within the 46px card, with the same dimensions at the header and bottom. Keep the compact header tight and move the title area up without a separate toolbar row. The touch editor keeps its app header and canvas anchored together at the visible viewport origin before measuring the dock and popup portals. Clamp stale positive keyboard offsets against the retained unobscured height, preserve signed negative viewport origins, and remove only the previous app correction when measuring native panning. Frame correction does not scroll the page; clear it when zooming, leaving the editor, or returning to fine-pointer controls. Recheck the writing band when the frame correction changes even if the dock returns to the same screen position. The dock uses visible-viewport coordinates relative to this app frame, follows keyboard transitions, and respects the bottom safe area. The header dock does not remove the need for writing and popup clearance above native browser and keyboard controls: Apple touch browsers reserve room for both the address pill and input accessory row. Publish one usable band for caret protection and every compact popup. A measured page reserve includes the complete space needed to move the final writing line above the dock, including keyboard and native browser controls. Caret protection checks the achieved position after an edit or browser scroll, with bounded corrections and no control changes to the native selection. Compact dock buttons use flat ghost styling at rest, with deliberate hover, pressed and keyboard-focus cues. Commands require a current prose caret or selection; title and metadata focus do not reuse an old canvas selection. Outline/Details and writing popups are mutually exclusive. Touch devices with no detected fine pointer use native text selection exclusively; Fieldbook does not render its selected-text popup or Format trigger there. Commands opens insertion tools, even with selected text. An explicit insertion action snapshots its target and preserves a temporary visible text highlight, where CSS custom highlights are supported, while menu focus clears the native DOM selection. This paint does not change document markup or restore native handles; remove it on return, dismissal, or target invalidation. Menus remain inside the measured band below the top dock or above the bottom dock, keep the dock visible, and scroll internally with a reachable close action. Dismissal restores the writing target. Opening a touch toolbar menu on a completed tap remembers the writing target and dismisses the keyboard; closing through its toggle, Cancel or Escape restores that target and focus within the user gesture. Input fields inside Details or upload choosers open the keyboard only when selected. Discard saved cursor positions when their field or document has changed. Typed slash search remains in typing mode. Mouse desktop contextual formatting remains unchanged. Reserve enough scroll space for the final writing line and reveal the caret inside the actual usable writing band, including browser panning. Typing and deliberate caret changes keep the active row clear of the dock and native controls without moving the toolbar toward the caret. Read neighboring-character geometry when a browser omits a collapsed caret rectangle. Ordinary manual scrolling does not pull the canvas back to an unchanged caret. Compact Outline and Details panels open centered inside the usable band, one at a time, with their own scrolling. Visible save-error notices and recovery actions stay clear of the panels. Hide the dock while the app navigation drawer or header search is open. Desktop placement, balanced canvas gutters and the existing compact-layout cutoff remain unchanged. The writing surface is borderless, with a pinned document title or current lesson heading. Desktop authors insert blocks with the slash menu and format selected text with contextual controls. Desktop navigation retains one vertically centered row. The reading column narrows only as needed to preserve minimum clearance for the edge buttons, a small gap and the Back button padding; Back stays aligned with the canvas titles. This applies with an expanded sidebar and enlarged text. Back remains visible on desktop even when search independently switches to its icon. App navigation and extra writing controls share one compact mode, which also switches search to its icon: phone widths below 768px, or portrait touch tablets below 1280px. Other viewports retain the desktop sidebar and search field. Switching navigation layouts restores the saved desktop sidebar width immediately; animate only deliberate sidebar toggles. Compact authors use the existing app navigation and account menu to leave the editor. Commands and undo/redo appear in the thin floating toolbar only at phone widths or on portrait touch tablets with no reported mouse or trackpad; narrow mouse windows retain the compact in-page row and contextual formatting, and other layouts retain slash insertion and contextual formatting. Compact layouts use a search button that opens a full-width field. Switching between the search field and icon closes the panel while preserving the query. Markdown download lives in Details and exports the active document or lesson. Below Recovery, a divider precedes the red Delete Doc, Delete Course or Delete Update button. It uses the content list’s existing deletion confirmation and 30-day recovery warning. Deletion waits for saved edits and completed uploads; a failed deletion keeps the editor open. Canvas titles use a compact inset below desktop navigation or the compact app header. Course and lesson headings keep a modest gap; the lesson eyebrow sits close to its title. Lesson titles use 28px type with 36px leading, subordinate to the 32px course title. The course title scrolls above the lesson or Quiz heading. Quiz shares the lesson title typography and pinned behavior; its outline actions contain only Delete quiz. Question delete controls appear only with multiple questions, and answer delete controls only above two answers. Removal handlers retain these minimums. The selected outline lesson keeps one actions menu beside its title for reordering, duplication and removal. Every lesson reserves the same action space so titles keep their width, and hover covers the entire row. Lesson menus open beyond the outline surface to its right when space allows; narrow overlay layouts keep menus within the viewport. Outline and Details share the same floating surface at the outer workspace edges, with a width of 320px, constrained only when the viewport is smaller. Entering a content editor collapses the main sidebar, which authors can reopen with its toggle. The text column stays centered at the reading width, narrows fluidly on smaller screens and uses balanced side padding. Compact canvases reserve equal 44px block-action gutters on both sides, keeping Back, titles and writing aligned on a centered column. The compact dock retains 44px-high targets and equal space around its controls. Non-text blocks reserve space before the next writing line. Use block display for their decorators to avoid anonymous inline line boxes; keep the same gap when media is followed by text in its paragraph. Standalone videos use block nodes while videos within text keep their inline representation; both export the same ordinary Markdown media links. Lists insert native empty list items immediately so marker style, indent and caret geometry remain stable through typing, pasting and composition. Block menus stay just outside each element’s top-left corner and remain visible in compact mode; tables keep their row/column control space rather than moving the block menu above the table. Menu toggles never change the column width or position. Menus use the surrounding space when it fits and otherwise overlay the canvas. Keep their headings fixed and scroll only the body, with subtle content-edge fades that preserve the card border, shadow and bottom padding. Docs and Updates start with Details open, and Courses with Outline open, only when the preferred menu clears the text column. Otherwise menus start closed. Narrowing closes an open menu when it first crosses into the text; authors can deliberately reopen it as an overlay. Widening does not automatically reopen menus. Touch dock menus overlay the canvas inside the usable band without changing its width or overlapping the dock. Desktop menus may stay open together when they fit; compact menus always open one at a time. Their external toggle remains the close control. Mouse layouts return focus to that toggle; touch dock menus restore the saved writing target. A restored text selection reveals its focus edge inside the usable band while retaining the selection; manual selection dragging keeps control. Moving from Commands to a media chooser retains the insertion target without briefly reopening prose input. Publishing requirements smoothly reveal their target, respecting reduced motion: titles receive a spacious attention outline only for guided publishing navigation, empty writing canvases receive a caret on their first line, and quiz requirements reveal the question section without selecting an individual field. Direct title clicks and ordinary keyboard focus stay borderless; a deliberate click or blur clears the publishing highlight without moving the text. Keep the native title field square so it does not round or clip the caret and text selection; rounding belongs to the separate attention outline.

Desktop content canvases keep blank space below the final block equal to about 30% of the usable writing area. Place this physical reserve inside the top-level writing content and size it from the active canvas or page scroller. Existing blank room in a short canvas counts toward the reserve. Keep the space stable through focus and menu changes, preserve the writing position as the layout changes, and retain the current automatic scrolling behavior. The reserve is interface layout and is never saved as content. Touch-only editors use their measured dock clearance; the desktop comfort allowance does not add to it.

Pasting a web address over selected prose applies a link while preserving its wording and inline formatting, including in table cells. Recognizable bare domains use HTTPS. Link paste is one undoable edit; ordinary text, code and media pastes retain their existing behavior.

The workspace owns normal page scrolling. Nested lists may scroll when bounded, but short screens and enlarged text must still reach every control. Do not solve a sizing problem with a global overflow lock. Tables and horizontal strips scroll within their own containers without trapping vertical page scroll.

Use semantic elements, accessible names, visible focus, and keyboard-operable controls. Check the states and layouts affected by the change, including empty, loading, error, disabled, selected, long-content, and enlarged-text states where relevant. Review desktop, tablet, and phone layouts when the change can affect them. Exercise affected interactions such as filtering, opening menus, and saving.

Details orders publishing requirements, short description, organization, Assign, Quiz settings when a course has a quiz, artwork, course duration and version, then Recovery. The quiz passing requirement is edited in Details; the quiz canvas points authors there. Hide publishing guidance when no requirements remain. Short descriptions show a live 300-character count. Details inputs, textareas and picker searches use the metadata control variant to retain the smaller label/copy typography at every width. Other controls retain their default responsive type sizing. Category and section pickers grow through five options, then scroll with subtle edge fades. Draft Courses keep audience assignment visible but disabled until publication; audiences remain optional. Published Updates retain their optional feed-renewal control.

Uploaded videos use native browser playback controls, including their speed menus; do not add a second speed selector below the player. Native control appearance follows the browser. Image uploads offer an optional Alt text field without blocking file selection; omitted text retains the filename fallback, and authors can edit it later. Meaningful descriptions remain useful for informative images.

Pasted images and command-uploaded images or videos use the same quiet muted Loading… bar with a small spinner at the insertion point, then replace it with the media. The spinner respects reduced motion and never changes the bar height. Keep upload feedback out of the space above the editor so navigation and pinned titles do not move. Loading blocks are temporary editor state and never saved in Markdown; an upload failure restores the original text and retains the existing error and retry behavior. The image-fetch placeholder uses the same bar instead of a dashed image icon. Lazy editor startup reserves a silent busy surface instead of flashing a loading sentence. Disabled contextual navigation stays transparent during upload; normal hover and focus cues return when navigation is available. Image-only paragraphs hide their managed caret line inside the block wrapper while retaining normal spacing below the block. Restore the caret to the first following writing line after upload releases read-only mode; reuse existing lines and preserve intentional blanks.

Text selections exclude adjoining blocks when their endpoints contain none of those blocks’ content, for deletion, replacement, copying, and formatting. Clipboard import drops empty trailing styled-block artifacts and preserves the original style of untouched text after a rich-text paste; meaningful pasted headings retain their formatting. Deliberate paragraph joins and selections that include actual text in the next block keep normal editing behavior. Contextual formatting targets the editor owning the native selection, including table cells, and refreshes its target when switching editors.

Media-only paragraphs contain content even without text. Inserting or formatting adjacent blocks must preserve the media and existing heading styles; heading formatting across prose leaves media-only paragraphs unchanged. A document ending in media retains a writable paragraph below it, including media inside a list or callout. Nested media uses the same spacing as standalone media without an extra caret line inside its wrapper. Multiple pasted images retain clipboard order, share one undo step, and restore the original document if an upload fails. Editing commands use the current native selection, preserving its direction, before applying block-boundary rules.

## Verify interface work

When adding or changing a shared component, show representative states in the demo's `/ui` catalog using the actual component, and document any non-obvious usage or accessibility rules. The catalog uses synthetic content; it does not supply runtime components to the installed interface.

Run `pnpm check:ui` and relevant browser tests for the changed behavior. Review both apps when shared behavior changes.

Before running demo browser tests, build the demo and install the Playwright browser if needed. Available test commands are in `package.json`. Review the resulting screenshots as well as test output. A local browser check does not prove a hosted installation's authentication or data behavior.
