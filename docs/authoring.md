# Writing Docs and Updates

Docs and Updates have separate **Save draft** and **Publish** actions. Saving a draft keeps the editor open and leaves the published copy unchanged. **Publish changes** replaces the published copy with the current work. **Preview draft** shows the working copy using the same Markdown renderer as readers. Unpublish remains a separate, confirmed action in the content list; it preserves the draft.

The editor shows unsaved work and save results. Cmd/Ctrl+S saves a draft, never publishes. There is no automatic draft saving. Navigation warns about unsaved work; uploads block saving and navigation until they finish. Failed saves retain the open work. If another author changed the document or the outcome of a save is uncertain, use **Review saved copy** and **Download draft** before reapplying changes. Those tools are in **More writing actions** and are also shown beside recovery errors.

The visual editor supports headings, emphasis, lists, quotes, links, tables, code blocks and images. Uploaded MP4/WebM media displays inline and remains an ordinary media link in storage. Markdown source is available for precise edits and unsupported constructs, including footnotes. Unsupported imports fall back to source and preserve the original text. Image resizing is intentionally unavailable because it would introduce HTML dimensions that the reader does not support.

Docs, Updates and course lessons use the same writing controls. The compact toolbar keeps text style, Undo, Redo, Bold, Italic, links and lists visible. **Insert** opens the shared menu for headings, lists, callouts, tables, code and media; typing `/` at the start of a line opens those choices at the caret. The toolbar wraps on narrow screens. Undo and Redo change the current editor content; they do not undo a save or publication, or delete an uploaded file from storage.

New Docs and Updates start without an assigned section/category. For Docs, search the section picker and choose one full path; a document belongs directly to either a top-level section or one subsection. **Create section** accepts a name and optional top-level parent, saves it separately, and selects it. Save the document to keep that placement. Docs navigation settings manage renaming, placement and order. Update settings choose a category and relevant learning groups. Groups personalize recommendations, never content access. Settings collapse on narrow screens. Privacy authoring retains its Markdown editor.

## Building a course

A new course starts with Lesson 1. The desktop Course Outline or mobile step picker selects one lesson at a time; add, rename, reorder, duplicate or remove lessons there. Add one optional Quiz, which always stays after the lessons. The course title and short description are above the settings on desktop and above the editor on mobile. Lessons use the shared visual editor, Markdown source fallback and learner-like draft preview. Insert and `/` at the start of an empty paragraph offer the same supported blocks and media, including tables. On a blank line, the editor shows a hint; typing `/` shows the search text at the caret and opens a command menu beside it. Type to filter, use the arrow keys and Enter to select, or Escape to close it. If nothing matches, Enter keeps the typed slash text in the lesson; clicking another line also closes the menu. Heading, list and callout commands keep the caret in the selected block. Image and video commands open an upload/link chooser at the insertion line. Images can also be pasted into the visual editor when the installation has media storage; the filename supplies initial alternative text, which authors should review. Tables start as a 3×3 grid. Row, column and delete controls appear when the table is active, and an open row or column menu closes if the table scrolls. Wide tables keep readable columns and scroll inside the table in both the editor and reader. Video links may be YouTube, Vimeo, Loom or direct HTTPS MP4/WebM. Provider sharing settings govern external embeds, so check visibility before publishing. Include captions with the source video or a transcript in the lesson when speech matters.

Fieldbook accepts MP4/WebM files up to **50 MB each**, with no duration limit. It stores uploads in private Supabase Storage and serves them through authorized media URLs. It does not encode or transcode files; prepare browser-playable MP4/WebM before uploading. A 50 MB file can represent very different durations and start times depending on its bitrate and the viewer's connection. Use a short, compressed test clip to check playback, seeking and captions before publishing a long lesson.

Quiz questions have two to five answers, one to four marked correct, and at least one incorrect answer. The player uses radio choices for one correct answer and checkboxes for multiple correct answers. It shows one question at a time and grades the full attempt after the last answer. The results screen shows the score, review, retry when answers were missed, and optional feedback. An optional explanation appears after grading. New courses default **Require all answers correct to complete** off. With it off, submitting every quiz answer completes the course even if some answers are wrong; with it on, learners may retry until every question is correct. The final lesson completes a course without a quiz and opens the finish screen with feedback expanded. Close course only navigates away. Saving a draft does not publish it. Changing a published course's completion rule requires a new course version so earlier progress is not silently reinterpreted.

## Implementation and extension

`WritingEditor` is a shared presentation pattern. It does not save, publish, authorize or upload on its own. Its owner supplies a Markdown value, change callback, busy state and the existing authorized upload handler. MDXEditor 4.2.5 provides the Lexical editing engine; the toolbar uses Fieldbook controls and MDXEditor's contextual block selector. Both Insert and `/` use one command list. Future course-specific interactions can extend that list for course lessons while retaining the shared editor; their stored format and reader behavior need separate design. The scoped stylesheet maps nested editor UI to Fieldbook tokens. This does not replace the shared component library.

The engine is dynamically imported with server rendering disabled inside a client component, as required by MDXEditor. Reading remains server-rendered Markdown. Keep editor plugins and Lexical imports within this lazy boundary. Root and server manifests must resolve the same editor, state and Lexical versions.

Import normalization must not mark an untouched document dirty or rewrite it when only its title changes. The compatibility guard compares Markdown syntax trees before accepting normalized imports. Unknown or incompatible content must retain its original source, never silently become an empty document. Runtime editor failures also fall back to source. The video adapter preserves the reader's existing `/api/media/*.mp4` and `.webm` link format. It does not execute MDX/JSX.

The demo upgrades existing browser work to separate draft and published snapshots without resetting profiles or content. It cannot reconstruct a historical publication already overwritten by an older demo save. The server already stores separate snapshots; this interface change requires no database migration.

Run the authoring suite after both builds. It covers existing-content round trips, formatting/undo, source fallback, repeated draft saves, publishing, unpublishing, failure recovery and pending uploads. Tests use synthetic server responses; they are not proof of hosted authentication or Storage behavior.
