# Writing Docs, Updates and Courses

Docs, Updates and Courses automatically save edited drafts while keeping the editor open. The quiet status in the editor header shows **Saving**, **Saved** or a save failure. Draft saves leave the published copy unchanged. **Publish** publishes a draft; **Publish changes** replaces a published copy with the current work. When the current work matches the published copy, **Published** is disabled. Reverting an edit restores that state. **Preview draft** uses the same Markdown renderer as readers. Unpublish remains a separate, confirmed action in the content list; it preserves the draft.

An untouched new editor does not create a record. Incomplete titles, placement and quiz answers can be saved as drafts; **Publish** stays unavailable until the existing publication requirements are met. The required-item count on **Details** leads to a checklist; choose a requirement to reveal its field, lesson or quiz. The target scrolls smoothly into a comfortable position with its label visible. Details fields scroll their panel; title and lesson fields use the main editor viewport when needed. On narrow screens, if a stacked panel itself is offscreen, the main viewport also brings that panel into view. If an open Outline has hidden the selected lesson, that row scrolls into view independently without taking focus from the field. Visible targets stay in place, and reduced motion skips the animation. Cmd/Ctrl+S requests a draft save, never publication. Leaving the editor waits for pending saves; uploads block saving and navigation until they finish. Failed saves retain the open work. If another author changed the document or the save outcome is uncertain, automatic saves stop. The header shows **Changes not saved**; an alert below it holds the actions to retry safely, download your changes or deliberately load the saved draft. Closing the browser before a save finishes cannot guarantee persistence; wait for **Saved**.

The visual editor supports headings, emphasis, lists, quotes, links, tables, code blocks and images. Uploaded MP4/WebM media displays inline and remains an ordinary media link in storage. Markdown source is available for precise edits and unsupported constructs, including footnotes. Unsupported imports fall back to source and preserve the original text. Image resizing is intentionally unavailable because it would introduce HTML dimensions that the reader does not support.

Web links can omit the protocol: entering `example.com/guide` saves `https://example.com/guide`. Readers also recognize bare domains in existing Markdown without changing the stored draft. Relative paths, file links and heading fragments retain their meaning. The link popup stays beside its text as the writing canvas scrolls or changes width. Portaled formatting and link tools keep the active outline around their originating editor; dismissing the tools clears it when focus leaves writing. Command menus use one immediate mouse/keyboard highlight, and only keyboard selection scrolls hidden choices into view. Outline and Details slide open and closed, keep closing controls unavailable to focus, and skip motion when reduced motion is enabled.

Docs, Updates and course lessons use the same writing controls. The compact toolbar keeps Undo, Redo and **Commands** visible and stays below the editor heading while you scroll. The page scrolls the editor into place beneath the heading, then the document scrolls inside that frame while the toolbar and rounded outline stay visible. Write content grows automatically inside a viewport sized to the available screen space; no manual canvas resizing is needed. Scrolling upward at the document’s beginning returns to the course/content title. Very short screens retain page scrolling so the tools and content remain accessible. Focusing the editor highlights one rounded frame around both the toolbar and canvas; Markdown uses the same frame. With a caret, Commands opens the same block menu as `/` at the start of a line: Normal Text, Heading 1–4, lists, callouts, tables, code and media. Highlighting text opens a separate floating formatting panel, with a Normal Text/heading picker and Bold, Italic, Link and Inline code. Commands also opens that panel for selected text, including keyboard entry. Escape closes the command menu; clicking away or scrolling also closes it and preserves an unfinished slash query as text at its original line. Familiar editing shortcuts remain available. The toolbar wraps on narrow screens. Undo and Redo change the current editor content; they do not undo a save or publication, or delete an uploaded file from storage.

New Docs, Updates and Courses start without an assigned section/category; the category picker prompts you to choose or add one. For Docs, search the section picker and choose one full path; a document belongs directly to either a top-level section or one subsection. **Create section** accepts a name and optional top-level parent, saves it separately, and selects it. Draft autosave keeps that placement. Docs navigation settings manage renaming, placement and order. Update details choose a category and relevant learning groups. Groups personalize recommendations, never content access. The compact header keeps Back to content on the left and save text, unpublished-edit text when applicable, the Draft/Published pill and Publish in one line on the right. The title sits below it, above one writing workspace. Its persistent **Details** toggle opens an in-page panel for readiness, short description, placement, artwork and other metadata. On wide screens the panel sits beside the canvas; on phones it expands above it. It starts closed and does not replace the writing surface. The Outline/Details row stays directly beneath the fixed editor header while scrolling; the writing surface fills the space between open panels. Privacy uses the shared writing editor with its existing Save settings and Publish controls.

Published content offers **Revert to published version** at the bottom of Details. Confirming discards unpublished edits and restores the current publication into the working draft, which saves automatically. It does not publish, change assignments or reset learner progress. The action is unavailable when the draft already matches its publication and is absent for content never published.

If a save fails, the editor preserves open changes and shows **Changes not saved**. **Retry saving** first checks the latest saved draft; it resumes only when that state matches the previous baseline or the attempted save. Conflicting work remains open until you deliberately **Load saved draft** and confirm replacement. **Download your changes** saves the current draft as a JSON backup and is offered only after a failed save. A missing or deleted saved draft is never recreated automatically.

## Building a course

A new course starts with one untitled lesson. Its title field shows the muted **Untitled lesson** placeholder; added lessons also start with a blank title. The outline uses positional names such as Lesson 1 until you name them. The left outline starts open and selects one lesson at a time. One persistent **Outline** toggle collapses or reopens it in the workspace and shows the current lesson position, such as **Lesson 1 of 3**, or **Quiz**. Add lesson and Add quiz stay visible in the outline; the selected lesson has inline move-up/down controls and a Lesson actions menu for duplication and removal. Long outline titles are shortened visually while their full names remain available to assistive technology and on hover. There is no alternative drawer. Wide workspaces can show Outline and Details together; laptop widths show one auxiliary panel at a time. On phones each panel expands above the canvas, and selecting a lesson returns to writing. Collapsing a panel keeps the current lesson and writing surface mounted. Switching lessons keeps a visible writing frame in place and opens the new lesson at its beginning. If the frame is offscreen, the main viewport briefly reveals it before the new lesson replaces it; reduced motion skips the animation. Short lessons retain enough canvas height to hold that position. Ordinary navigation focuses the writing region, while publishing-checklist links still focus their requested fields. Rename a lesson in the centered input between Outline and Details in the fixed workspace row. Its text is left aligned and smaller than the course title. The field stays centered when panels close; on narrower screens it sits beneath the toggles with enough writing room. With both panels closed, writing text has a centered maximum width and side padding while the toolbar keeps its full width. Collapsing the app sidebar as well adds more side padding to that text measure. Opening either panel retains the fluid writing layout. Content and lesson title fields share the same preferred width and shrink to fit narrow workspaces; the writing canvas still uses the available width. One optional Quiz always stays after the lessons. The course title sits above the writing workspace; its short description lives in Details alongside the other content metadata. Lessons use the shared visual editor, Markdown source fallback and learner-like draft preview. Write, Markdown and Preview draft use underline tabs in the gray toolbar header across Docs, Updates and Courses, with muted inactive labels and a dark active underline. Arrow keys move between views. There is no separate content-label row or repeated slash instruction. View controls remain available while the visual tools load and when source recovery opens. Commands and `/` at the start of an empty paragraph offer the same supported blocks and media, including tables. On a blank line, the editor shows a non-interactive hint over the empty paragraph, with the caret at its beginning; typing `/` shows the search text at the caret and opens a command menu beside it. Type to filter, use the arrow keys and Enter to select, or Escape to close it. Escape works with focus in the canvas or menu, returns focus to writing or the Commands button, and preserves a typed slash search as ordinary text. If nothing matches, Enter keeps the typed slash text in the lesson; clicking another line also closes the menu. Heading, list and callout commands keep the caret in the selected block. Image and video commands open an upload/link chooser at the insertion line. Images can also be pasted into the visual editor when the installation has media storage; the filename supplies initial alternative text, which authors should review. Tables start as a 3×3 grid. Row, column and delete controls appear when the table is active, and an open row or column menu closes if the table scrolls. Wide tables keep readable columns and scroll inside the table in both the editor and reader. Video links may be YouTube, Vimeo, Loom or direct HTTPS MP4/WebM. Provider sharing settings govern external embeds, so check visibility before publishing. Include captions with the source video or a transcript in the lesson when speech matters.

Fieldbook accepts MP4/WebM files within the installation's configured application and storage limits, with no duration limit or fixed 50 MB application ceiling. It stores uploads in private Supabase Storage and serves them through authorized media URLs. It does not encode or transcode files; prepare browser-playable MP4/WebM before uploading. A file's duration and start time depend on its bitrate and the viewer's connection. Larger files use chunked uploads with progress and bounded automatic retries after interrupted chunks; the current transfer resumes from its confirmed offset. Signed credentials are not kept in browser storage for recovery after closing the page. If signing, storage or final verification fails, the editor keeps its text and inserts no media reference; choose the file again to start a fresh attempt. Publishing and leaving the editor remain blocked during the active upload. Use a short, compressed test clip to check playback, seeking and captions before publishing a long lesson.

Quiz questions have two to five answers, one to four marked correct, and at least one incorrect answer. The player uses radio choices for one correct answer and checkboxes for multiple correct answers. It shows one question at a time and grades the full attempt after the last answer. The results screen shows the score, review, retry when answers were missed, and optional feedback. An optional explanation appears after grading. New courses default **Require all answers correct to complete** off. With it off, submitting every quiz answer completes the course even if some answers are wrong; with it on, learners may retry until every question is correct. The final lesson completes a course without a quiz and opens the finish screen with feedback expanded. Close course only navigates away. Saving a draft does not publish it. Changing a published course's completion rule requires a new course version so earlier progress is not silently reinterpreted. The new-version option is staged through draft saves and consumed only by a successful explicit publication; background draft saving does not reset progress or assignment windows.

## Implementation and extension

`EditorFrame` owns the inline Outline/Details panels and their responsive presentation. It does not save content or change publication rules. `WritingEditor` is a shared presentation pattern. It does not save, publish, authorize or upload on its own. Its owner supplies a Markdown value, change callback, busy state and the existing authorized upload handler. MDXEditor 4.2.5 provides the Lexical editing engine; the toolbar uses Fieldbook Undo, Redo and Commands controls. Retired block, inline-format and list toolbar buttons are removed, along with their control-only state and CSS. Commands with a caret and `/` use one block-command list; selected text has a separate formatting panel built from shared popover/dropdown controls. Both surfaces share the supported block styles and restore their captured editor selection before applying a command. Future course-specific interactions can extend that list for course lessons while retaining the shared editor; their stored format and reader behavior need separate design. The scoped stylesheet maps nested editor UI to Fieldbook tokens. This does not replace the shared component library.

The engine is dynamically imported with server rendering disabled inside a client component, as required by MDXEditor. Reading remains server-rendered Markdown. Keep editor plugins and Lexical imports within this lazy boundary. Root and server manifests must resolve the same editor, state and Lexical versions.

Import normalization must not mark an untouched document dirty or rewrite it when only its title changes. The compatibility guard compares Markdown syntax trees before accepting normalized imports. Unknown or incompatible content must retain its original source, never silently become an empty document. Runtime editor failures also fall back to source. The video adapter preserves the reader's existing `/api/media/*.mp4` and `.webm` link format. It does not execute MDX/JSX.

The demo upgrades existing browser work to separate draft and published snapshots without resetting profiles or content. It cannot reconstruct a historical publication already overwritten by an older demo save. The server already stores separate snapshots; this interface change requires no database migration. The shared draft-save queue serializes revision-checked writes and keeps newer typed edits when a slower response arrives. Publication remains an explicit request using the latest work.

Run the authoring suite after both builds. It covers existing-content round trips, formatting/undo, source fallback, repeated draft saves, publishing, unpublishing, failure recovery and pending uploads. Tests use synthetic server responses; they are not proof of hosted authentication or Storage behavior.
