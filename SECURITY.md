# Security reporting

Do not publish exploit steps, credentials, personal data or vulnerable installation details in a public issue or pull request.

If GitHub offers **Report a vulnerability** in this repository's **Security** tab, use it to send the maintainer a private report. Include the affected Fieldbook version or commit, a minimal reproduction, impact and a safe way to contact you. If that option is unavailable, open a public issue containing only a request for a private security contact; leave all vulnerability details out of the issue. The maintainer can then arrange a private channel.

Operators are responsible for securing and updating their own Vercel, Supabase, Google and domain accounts. A report about one installation's credentials or data should first go to that installation's operator through its published contact method. Do not post its secrets here.

There is no promised response time or supported-version window. See the [maintainer release process](docs/releases.md) for verification and release notes.
