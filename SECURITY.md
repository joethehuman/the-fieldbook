# Security reporting

Do not publish exploit steps, credentials, personal data, or vulnerable installation details in a public issue or pull request.

If GitHub offers **Report a vulnerability** in this repository's **Security** tab, use it for a private report. Include the affected Fieldbook version or commit, a minimal reproduction, impact, and a safe way to contact you. If that option is unavailable, open a public issue asking only for a private contact; leave the vulnerability details out of it.

Each installation's operator is responsible for its own Vercel, Supabase, Google, and domain accounts. Report an installation-specific credential or data incident to that operator through its published contact method.

There is no promised response time or supported-version window.
